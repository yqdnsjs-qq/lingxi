# 宇之语·灵犀 v3.0 安装部署手册

> 适用版本：v3.0
> 覆盖：本机版（管理员 / 用户）、服务器版
> 最后更新：2026-10-22

---

## 〇、先搞清楚你要装哪个

| 你要干什么 | 装哪个 |
|---|---|
| 自己电脑上用（不管你是管理员还是普通用户） | **本机版**（通用，一个包） |
| 多人共用一台服务器，各自看各自的文件 | **服务器版** |
| 已经从 v2.x 装过了 | 看《升级部署手册-v3.0.md》 |

> **本机版是"通用版"**：不再分管理员包 / 用户包 ✗
> 装一次，**谁登录都能用全部本机功能** ✓
>
> 管理员和普通用户的唯一区别：**能不能操作服务器**（本机都能建库、打标、索引）。
> 详见 §1.4。

> **三者是同一份代码**，区别只在于配置和"是不是建库机"。
> 判断标准在代码里：`run/deploy/sync_db.py` 这个文件**在** → 建库机（本机版）；
> **不在** → 服务器版。所以**别手动复制这个文件**到服务器上。

## 一、本机版（通用）

### 1.1 环境要求

| 项 | 最低 | 推荐 |
|---|---|---|
| 系统 | Windows 10 64 位 | Windows 11 |
| 内存 | 8 GB | 16 GB 以上 |
| 硬盘 | 20 GB 可用 | 50 GB 以上（索引库会变大） |
| 显卡 | 不需要 | NVIDIA 显卡 6 GB 显存以上（快 10 倍） |

内部校验：Python 3.12、PyTorch、transformers 都装在包内 `venv\` 里，
**不动系统 Python、不改注册表、不改 PATH** ✓

### 1.2 安装

1. 把 zip 解压到一个**固定位置**，例如 `D:\灵犀\`
   - ⚠ 不要放在 OneDrive / 坚果云等同步盘里（索引库频繁写，同步盘会冲突）
   - ⚠ 路径里尽量不要有空格
2. 双击 **`setup.bat`**
   - 自动建 `venv\`、装依赖（约 10~30 分钟，看网速）
   - 中途问是否装 CUDA 版 PyTorch：有 N 卡选是
3. 双击 **`start.bat`**
   - 首次会下载嵌入模型（约 2 GB）到 `models\`
   - 加载完会自动打开浏览器

### 1.3 首次配置

1. 浏览器打开后，**创建管理员账号**（用户名 2~24 字，密码至少 6 位）
   - 第一个账号**自动是管理员**
2. 进「设置」，按需要调：
   - 「模型」→ 运行设备（有显卡选 `cuda`）
   - 「文件索引」→ 向量维度（推荐 256）
   - 「服务器连接」→ 以后要同步到服务器时再填
3. 进「文件夹」→ 添加要索引的目录 → 点「建立索引」

### 1.4 通用版：管理员和普通用户有什么区别

**结论：本机上的功能一模一样，唯一区别是"能不能操作服务器"。**

| 能力 | 本机 · 管理员 | 本机 · 普通用户 |
|---|---|---|
| 建库、加/删文件夹、建索引 | **能** ✓ | **能** ✓ |
| 图片打标、OCR、人物管理 | **能** ✓ | **能** ✓ |
| 改模型/维度等本机设置 | **能** ✓ | **能** ✓ |
| 备份、还原、拍快照（本机数据） | **能** ✓ | **能** ✓ |
| 自己的 API / Dify 配置 | **能** ✓ | **能** ✓ |
| **服务器上的管理动作**（全站备份、改别人的文件夹、改全站设置、审批用户） | **能** ✓ | **不能** ✗ |
| 看到的数据 | 按归属：自己名下 + 共享的 | 同上（**不是"看全部"**） |

判据只有一条：**这台机器是不是他自己的电脑**（代码里看 `run/deploy/sync_db.py` 在不在）。

- **本机**（有这个文件）→ 登录就有全部本机权限，**不看角色** ✓
- **服务器**（没这个文件）→ 管理动作必须管理员 ✗

所以「用户版」不是"被阉割的版本"——它只是**不能碰服务器**，
本机上该有的建库、打标、索引、备份一样不少。

> 数据可见性由 `config.ini` 的 `[multi] local_strict` 控制：
> - `yes`（默认）：本机也按归属隔离 —— 普通用户只看自己名下 + 共享的
> - `no`：本机所有人都看到全部（适合"这台电脑就是我一个人的"）
>
> 注意这是**数据可见性**，不是功能开关。哪怕 `yes`，普通用户照样能给他自己的
> 文件夹建索引。

### 1.5 给其他人开账号

管理员进「用户管理」（`/static/users.html`）：

| 想干什么 | 怎么做 |
|---|---|
| 直接给某人开号 | 「新建用户」→ 填用户名密码 → 创建（默认直接启用） |
| 让别人自己注册 | 打开「允许任何人自助注册」→ 对方注册 → 你点「审批通过」 |
| 不想让任何人注册 | 关掉那个开关（默认就是关的） |
| 给某人分配文件夹 | 「文件夹 → 归属」里改，或 `venv\Scripts\python.exe run\assign_owner.py --to <用户id>` |

### 1.6 用户自己改名 / 改密码

用户登录后打开 `/static/users.html`，顶部有「我的账号」：

- 改用户名：要填**当前密码**确认身份
- 改密码：要填**旧密码**
- 改完密码后，其它设备上的登录会失效（当前这台保留）

### 1.7 日常使用

| 操作 | 怎么做 |
|---|---|
| 启动 | `start.bat` |
| 停止 | `stop.bat` |
| 重启 | `restart.bat` |
| 看状态 | `status.bat` |
| 备份数据库 | `backup.bat` |
| 从备份恢复 | `restore.bat` |

### 1.8 配置说明（`config.ini`）

包里的 `config.ini` 已经**清空了所有敏感项**（API key、同步 token、Dify 密钥），
需要时自己填。常改的几项：

```ini
[server]
host = 127.0.0.1        # 只允许本机访问；要局域网访问改 0.0.0.0
port = 8199
open_browser = yes

[model]
device = auto           # auto / cuda / cpu
dtype = auto
modality = text_image   # 全模态很吃显存，按需改

[search]
index_dim = 256         # 只影响以后新建的文件夹

[multi]
local_strict = yes      # 通用版默认 yes：按归属隔离（普通用户才只看自己的）
allow_register = no     # 自助注册开关（也能在界面上切，那个立即生效）
```

改完**重启服务**生效（`restart.bat`）。

> `allow_register` 在界面上切换是**运行时生效**的（存在数据库 `meta` 表里）；
> 改 `config.ini` 只是改"默认值"，界面上的开关优先。

## 二·五、OCR 组件（可选，本机版）

### 先说结论

**OCR 不是必需的**。不装也能用灵犀 —— 只是：

- PDF 只能按**文件名**检索，不能提取正文
- 扫描件、截图里的文字提不出来
- 图片只能靠打标描述，不能 OCR

### 三个引擎，按需选一个

| 引擎 | 体积 | 显存 | 适合 |
|---|---|---|---|
| **RapidOCR**（推荐先用这个） | **0.26 GB** | 不占（纯 CPU） | 日常扫描件、截图、PDF 图片 |
| PP-OCRv6 | 3.8 GB | 要 GPU | 需要文字坐标、更高准确率 |
| MinerU | 11.6 GB | 要 GPU | 结构化 Markdown、表格、自动提图 |

> 三个引擎都跑在**独立环境**里（独立 venv 或完整运行时），通过子进程调用。
> 这么做是因为它们的依赖（paddle / onnxruntime）又大又重，混进主环境会把依赖搞乱，
> 而且显存要能独立回收。

### 装 RapidOCR（最简单，5 分钟）

1. 双击 **`install_ocr.bat`**
   - 自动建 `ocr-rapid\.venv\`、装 `rapidocr-onnxruntime`（约 260 MB）
   - 自动复制桥接脚本
   - 自动生成 `ocr-env.bat`（里面是引擎路径）
2. 重启灵犀（`stop.bat` → `start.bat`）
   - `start.bat` 已经会自动加载 `ocr-env.bat` ✓ 不用你手动改
3. 进「设置 → OCR」，「RapidOCR」那项应该显示可用

**验证**：随便找个有文字的图片或扫描 PDF，索引后在预览里看有没有文字。

### 装 PP-OCRv6（要 GPU，准确率更高）

```bat
:: 建独立环境（放在灵犀目录外面也行）
mkdir D:\GJ\PP-OCRv6
cd /d D:\GJ\PP-OCRv6
python -m venv .venv
.venv\Scripts\python.exe -m pip install paddlepaddle-gpu paddleocr

:: 放桥接脚本（包里有模板）
copy "灵犀\run\ocr_bridges\ppocr_bridge.py" .
```

然后设两个环境变量（写在 `ocr-env.bat` 里）：

```bat
set "EG2_OCR_PPOCR_PY=D:\GJ\PP-OCRv6\.venv\Scripts\python.exe"
set "EG2_OCR_PPOCR_BRIDGE=D:\GJ\PP-OCRv6\_lingxi_bridge.py"
```

> ⚠ PP-OCRv6 会占显存，和嵌入模型、打标模型抢 GPU。
> 灵犀内部有显存互斥锁（本地 OCR / 打标串行），但装之前先确认显存够。

### 装 MinerU（最强，也最重）

MinerU 有自己的一整套运行时（约 11.6 GB），按它官方文档装好后：

```bat
set "EG2_OCR_MINERU_PY=<MinerU>\runtime\python\python.exe"
set "EG2_OCR_MINERU_BRIDGE=<MinerU>\tools\submit_mineru_task.py"
set "EG2_OCR_MINERU_DIR=<MinerU>"
```

它还需要**先启动 MinerU 的 API**（`run-api.cmd`）。灵犀会检测它通不通，
设置页会显示「MinerU API 未运行」。

### 全部路径都可以改

`app/ocr.py` 里每个引擎的 python 和 bridge 都走环境变量（默认值指向开发机的
`D:\GJ\...`，所以你换成自己的路径即可）：

| 环境变量 | 对应 |
|---|---|
| `EG2_OCR_RAPID_PY` | RapidOCR 的 python.exe |
| `EG2_OCR_RAPID_BRIDGE` | RapidOCR 的 bridge.py |
| `EG2_OCR_PPOCR_PY` | PP-OCRv6 的 python.exe |
| `EG2_OCR_PPOCR_BRIDGE` | PP-OCRv6 的 _lingxi_bridge.py |
| `EG2_OCR_MINERU_PY` | MinerU 的 python.exe |
| `EG2_OCR_MINERU_BRIDGE` | MinerU 的 submit_mineru_task.py |
| `EG2_OCR_MINERU_DIR` | MinerU 根目录 |

### 服务器版要装 OCR 吗？

一般**不需要**：

- 索引是在**本机版**建的，OCR 也在本机跑
- 服务器只负责搜索和展示，不建库
- 除非你要在服务器上直接给新上传的文件做 OCR

真要在服务器装，走同样的思路（独立 venv + 环境变量，
写在 `lingxi.service` 的 `Environment=` 里）。

## 三、服务器版（Linux）

### 3.1 环境要求

| 项 | 要求 |
|---|---|
| 系统 | Ubuntu 22.04 / 24.04（其他发行版需自行调整） |
| Python | 3.12（推荐用系统自带 + venv） |
| 内存 | 8 GB 以上 |
| 硬盘 | 30 GB 以上（索引库 + 模型） |
| 显卡 | 不需要（CPU 也能跑，慢） |

### 3.2 部署步骤

```bash
# ① 解压到固定位置
sudo mkdir -p /home/lingxi && cd /home/lingxi
unzip 灵犀-v3.0-服务器版.zip

# ② 建环境（约 10 分钟）
bash install.sh

# ③ 装成系统服务（开机自启 + 挂了自动重启）
sudo cp run/deploy/lingxi.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now lingxi

# ④ 等 30 秒让模型加载完，看状态
sleep 30
curl -s localhost:8199/health | head -c 100
```

`install.sh` 做的事：建 `venv/`、装 `requirements.txt`、下载模型、初始化索引库。
**它不会**建系统用户、不会改防火墙、不会装数据库。

### 3.3 首次配置

1. 浏览器打开 `http://<服务器IP>:8199`
   - 应该**直接跳到登录页**（不是嵌入调试页 ✓）
2. 首次会要求**创建管理员账号**
3. 进「用户管理」→ 给其他人开账号（或打开「允许自助注册」）

### 3.4 ⚠ 服务器版必须知道的五件事

**① 服务器没有建库能力**
包里**故意不含** `run/deploy/sync_db.py`。代码靠这个文件判断身份，
没有它 → 服务器模式：不能建库、不能打标、不能改模型。
**别手动把这个文件复制上去**，否则服务器会变成"建库机"，出各种怪事。

**② 索引库和文件从本机同步上来**
在**本机版**上配好「服务器连接」→ 上传/同步。同步脚本会把索引库和文件推上来。

**③ 强制登录**
服务器上 `EG2_ENFORCE_LOGIN=1` 已经写在 `lingxi.service` 里。
未登录访问任何业务接口都是 401；页面请求会跳登录页。

**④ 注册默认关闭**
`[multi] allow_register = no`。要开就在「用户管理 → 允许任何人自助注册」打开
（运行时开关，立即生效，不用改文件）。注册出来的账号是"待审批"，还要管理员点通过。

**⑤ 账号数量等敏感信息不外露**
外网访问时 `/api/auth/status` 返回的 `users` 是 `null`，看不到"有几个账号"。

### 3.5 外网访问（两个方案）

**方案 A：Cloudflare Tunnel（推荐，不用开端口）**

```bash
# 服务器上装 cloudflared（需能访问 GitHub/Cloudflare）
# 然后在 Cloudflare 面板建 tunnel，指向 http://127.0.0.1:8199
```

优点：域名干净（`https://xxx.你的域名`）、自动 HTTPS、不开端口、家里 IP 变了也没事。
缺点：国内访问会被导到境外节点（法兰克福/阿姆斯特丹），首屏 8~9 秒。

**方案 B：公网 IP + 端口映射**

如果运营商封了 80/443，只能用非标准端口，域名后要带端口（不美观）。
此时可在 Cloudflare 面板用 **Origin Rules** 改回源端口，保持域名干净。

### 3.6 备份（强烈建议）

```bash
# 手动
cd /home/lingxi && python3 app/dbbackup.py save "说明"

# 定时（每 6 小时，保留 10 份）
crontab -e
# 加一行：
0 */6 * * * cd /home/lingxi && venv/bin/python app/dbbackup.py save "定时"
```

## 四、常见问题

### Q1：`setup.bat` 卡在装依赖

- 检查网络，或改 `config.ini` 的 `[download] mirror = https://pypi.tuna.tsinghua.edu.cn/simple`
- 公司网络可能需要代理

### Q2：启动后浏览器打不开

1. 看 `logs\server.log` 最后 30 行
2. 确认 `run\server.pid` 存在
3. 端口被占 → 改 `config.ini` 的 `[server] port`

### Q3：模型加载失败 / 显存不足

- 改 `[model] device = cpu`（慢但一定能跑）
- 或 `modality = text`（只加载文本编码器，省一半显存）

### Q4：网络换地方后连不上服务器

本机版支持**多地址自适应**：`config.ini` 里可以写多个

```ini
[sync]
server = http://192.168.1.10:8199, https://lingxi.example.com
```

按顺序探测（各 2 秒），第一个通的就用 —— 在家走内网、出门走域名 ✓

### Q5：页面改了但浏览器还是旧的

按 **Ctrl + F5** 强制刷新。前端的 JS/CSS 文件名带内容哈希，理论上会自动更新；
但 HTML 本身可能被浏览器缓存，强刷一次就好。

### Q6：服务器上 `/docs` 打不开

**正常**。服务器版关掉了接口文档（`/docs`、`/redoc`、`/openapi.json` 都 404），
避免把接口结构暴露给公网。本机版仍然是开的（开发调试用）。

```
灵犀/
├─ app/                 主程序（Python + 前端）
│  ├─ server.py         入口

├─ run/
│  ├─ restart_server.py 重启
│  ├─ snapshot.py       源码快照
│  └─ deploy/
│     └─ sync_db.py     ★ 本机身份标记（服务器版没有这个文件）

├─ logs/                ← 运行日志
├─ backups/             ← 备份
├─ config.ini           配置
├─ setup.bat / start.bat / stop.bat ...（本机版）
└─ install.sh / run/deploy/lingxi.service（服务器版）
```
