# 宇之语·灵犀 升级部署手册（v2.x → v3.0）

> 适用：**已经部署过 v2.x**，要升到 v3.0
> 全新安装请看《安装部署手册-v3.0.md》
> 最后更新：2026-10-22

---

## 〇、升级前必读

### 这次升级改了什么（按影响排序）

| 变化 | 对你的影响 |
|---|---|
| **多人版**：归属隔离、共享、ACL | 原来所有文件夹都属于"0 号"（无主），升级后会归到现有管理员名下 |
| **账号体系**：`users` 表、会话 cookie、强制登录 | 服务器上未登录访问业务接口会 401；本机仍宽松 |
| **聊天**：会话保存、联网搜索、知识库、Dify、附件 | 新功能，不动老数据 |
| **新增表** | `chat_conversation`、`chat_message`（`IF NOT EXISTS` 自动建） |
| **新增 meta 键** | `auth.allow_register`（注册开关，运行时自动建） |
| **静态资源拆包** | `search.html` 从 305 KB 变成 38 KB + 独立 JS/CSS |
| **本机版合成通用版** | 不再分管理员包/用户包。**本机功能全开**（谁登录都能建库/打标/索引），管理员与普通用户的唯一区别是「能不能操作服务器」|
| **OCR 路径可配置** | 原来硬编码 `D:\GJ\...`，现在走环境变量（`EG2_OCR_*`），换机器不用改代码 |
| **前端地址变了** | `app/static/app.<哈希>.js|css`，旧的 `app.js` 已删 |

> **不需要手动跑 SQL**：新表和新键都是 `IF NOT EXISTS` / 运行时创建 ✓

### ⚠ 三个绝对不要做的事

1. **不要删掉 `data\index\index.db`** —— 那是全部索引，重建要几小时到几天
2. **不要覆盖 `config.ini`** —— 升级包不含它，但如果你手动复制整个文件夹就会覆盖
3. **不要把 `run\deploy\sync_db.py` 复制到服务器** —— 它是"本机/服务器"的身份标记

## 一、Windows 本机版升级

### 1.1 升级前（5 分钟，必做）

```bat
:: ① 停服务
stop.bat

:: ② 备份数据库（增量，很快）
venv\Scripts\python.exe app\dbbackup.py save "升级前"

:: ③ 备份配置
copy config.ini config.ini.bak-升级前
```

**如果没停服务就备份**：数据库是 WAL 模式，热备份可能拿到不一致的页。
`dbbackup.py` 内部会处理，但**停服务最保险**。

### 1.2 升级

1. 解压 `灵犀-v3.0-升级包.zip`
2. 把里面的 **`app\` 整个文件夹**覆盖到原目录（选"替换目标中的文件"）
3. **确认这几样没被动过**：
   - `config.ini`（你的配置）
   - `data\`（索引库）
   - `models\`（模型）
   - `venv\`（运行环境）
4. 如果有 `.bat` 脚本更新（`start.bat` / `stop.bat`），也一并覆盖

> **升级包的结构和安装包一样**，只是不含 `venv/`、`data/`、`models/`、`config.ini`。
> 所以你只复制 `app/` 和需要的 `.bat` 就行。

### 1.3 升级后

```bat
:: 启动
start.bat
```

1. 浏览器打开后 **Ctrl + F5 强制刷新**（前端拆包了，必须强刷一次）
2. 登录（如果之前没账号，会要求创建管理员）
3. 检查三件事：
   - 侧边栏「文件夹」能列出来
   - 搜索能返回结果
   - 人物页能看到人脸

### 1.4 升级后的数据归属

v2.x 的文件夹都是"无主"的（`owner=0`）。v3.0 启动后：

- **本机管理员**：自动看到全部（`local_strict = no`）
- **服务器**：无主的文件夹只有管理员能看，需要给具体人分配

给某人分配文件夹：

```bat
venv\Scripts\python.exe run\assign_owner.py --to 4
```

或者界面上「文件夹 → 归属」里改。

## 二、服务器版升级

### 2.1 升级前（10 分钟，必做）

```bash
cd /home/lingxi

# ① 停服务
sudo systemctl stop lingxi

# ② 备份数据库（务必）
venv/bin/python app/dbbackup.py save "升级前 v2.x"

# ③ 备份配置（升级包不含它，但保险）
cp config.ini config.ini.bak-升级前

# ④ 拍个源码快照（可选，出事了能对比）
bash run/deploy/snapshot_server.sh
```

### 2.2 升级

```bash
# ① 解压升级包到临时目录
cd /tmp && unzip 灵犀-v3.0-升级包.zip -d /tmp/lingxi-v3

# ② 覆盖 app/（保留 data/、models/、venv/、config.ini）
cd /home/lingxi
rsync -av --delete /tmp/lingxi-v3/app/ ./app/

# ③ ★ 确认服务器身份没被破坏
ls run/deploy/sync_db.py
# 期望：No such file or directory   ← 这是对的（服务器不该有）
# 如果存在了：rm run/deploy/sync_db.py

# ④ 启动
sudo systemctl start lingxi

# ⑤ 等模型加载（至少 25 秒，别急着测）
sleep 30
curl -s localhost:8199/health | head -c 120
```

### 2.3 升级后验证（5 项）

```bash
# ① 健康检查
curl -s localhost:8199/health | grep -o '"status":"ok"'

# ② 未登录必须被挡
curl -s -o /dev/null -w '%{http_code}\n' localhost:8199/api/folders
# 期望：401

# ③ 首页不能是嵌入调试页
curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' localhost:8199/
# 期望：302 → /static/search.html

# ④ 接口文档应关闭
curl -s -o /dev/null -w '%{http_code}\n' localhost:8199/docs
# 期望：404

# ⑤ 账号数不外露（外网时）
curl -s localhost:8199/api/auth/status | grep -o '"users":[^,]*'
# 外网期望：null   内网（本机）期望：数字
```

### 2.4 外网入口

如果之前用 Cloudflare Tunnel，升级后**不用改隧道配置**（还是指向
`http://127.0.0.1:8199`）。只需确认 cloudflared 进程还在：

```bash
ps aux | grep -c '[c]loudflared'    # 期望：1
docker ps | grep cloudflared        # 或看容器
```

## 三、回滚方案（升级出问题时）

### 3.1 最快回滚（5 分钟）

```bash
# 服务器
sudo systemctl stop lingxi
cp -r /path/to/旧的app备份/app ./app     # 或者从 snapshot 恢复
sudo systemctl start lingxi
```

**前提**：你在升级前备份了 `app/`。

### 3.2 数据库回滚（数据出问题时）

```bash
# 看有哪些备份
venv/bin/python app/dbbackup.py list

# 恢复指定一份
venv/bin/python app/dbbackup.py restore 20261022-010000
```

⚠ 恢复数据库会丢失备份之后的改动。**先停服务再恢复**。

### 3.3 完整回滚（回到 v2.x）

1. 用升级前的 `app/` 备份覆盖回去
2. 用升级前的数据库备份恢复 `data/index/index.db`
3. 恢复 `config.ini.bak-升级前`
4. 启动

## 四、升级后常见问题

### Q1：页面样式全乱了 / 图片不显示

前端拆包了（`app.<哈希>.js` + `app.<哈希>.css`）。如果旧的 `app.js` 还在：

```bash
ls app/static/app.*.js
# 应该只有一个带哈希的文件；如果还有 app.js（不带哈希），删掉它
```

然后 **Ctrl + F5**。

### Q2：登录后马上又被踢回登录页

外网走 HTTPS 时 cookie 要带 `secure`。v3.0 已按协议自动判断
（`X-Forwarded-Proto: https` → secure=True）。

如果还有问题，检查反向代理有没有传 `X-Forwarded-Proto` 头。

### Q3：普通用户看不到文件夹

v3.0 是**按归属隔离**的。v2.x 的数据升级后归属是"管理员"，
普通用户看到 0 个文件夹是**正常的**。

解决：让管理员给分配（界面「文件夹→归属」或 `run/assign_owner.py --to <用户id>`）。

### Q4：服务器上普通用户看到管理员的 API 模型

v3.0 已修（`prefs_all(inherit_sensitive=...)`）。
如果还看得到，检查 `app/chat_api.py` 里是不是旧版：

```bash
grep -c 'inherit_sensitive' app/chat_api.py    # 期望 > 0
```

### Q5：聊天发不出去（502）

检查 `eg2-rmhdr` 头有没有带上（opencode 需要 `x-opencode-session`）：

```bash
grep -c 'eg2-rmhdr' app/chat_api.py    # 期望 > 0
```

### Q6：`/docs` 打不开

**服务器上是故意的**（关掉了）。本机版仍然开放。

### Q7：新建聊天会话报 `[object Object]`

v3.0 已修（补了 `Content-Type: application/json`，错误信息也能读了）。
确认 `app/static/app.<哈希>.js` 里有 `Array.isArray(d)`：

```bash
grep -c 'Array.isArray(d)' app/static/app.*.js    # 期望 1
```

## 六、版本对照

| 项 | v2.x | v3.0 |
|---|---|---|
| 账号 | 单用户/无 | `users` 表 + 会话 cookie + 角色 |
| 隔离 | 无 | 归属 / 共享 / ACL 三级 |
| 聊天 | 无 | 会话保存 + 联网 + 知识库 + Dify + 附件 |
| 前端 | 单文件 305 KB | 38 KB HTML + 独立 JS/CSS |
| 服务器 | 无身份区分 | `sync_db.py` 标记；无该文件 = 服务器 |
| 接口文档 | 都开 | 服务器关闭 |
| 注册 | 无 | 开关（默认关）+ 审批 |
| API 共享 | 无 | `share`（全体）/ `share_to`（指定人） |
