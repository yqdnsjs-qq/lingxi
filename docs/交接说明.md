## 项目是什么

**宇之语 · 灵犀** —— 本地文件检索与知识中枢，部署在 `D:\lingxi`。

```

栈：  Python 3.12 + PyTorch CUDA + FastAPI + 单页 HTML
```

## 上一个会话（本轮）做了什么

1. **stop.bat 不关界面窗口 —— 找到真原因并修好**
   - 真因：`stop.bat` 里关窗口那两行 `taskkill` 落在 `exit /b 0` 之后、`:kill_service_windows`
     之前，**没有标签、是死代码**；而且 `call :kill_service_windows` 在 stop.bat 里根本不存在
     → 界面窗口从来没被关过，每启动一次多留一个（实测残留 7 个）。
   - 顺带：按窗口标题杀本来就不可靠（标题是中文、受代码页影响，实测 `PostMessageW` 都拿不到）。
   - 现在：新增 `app\close_ui.py`（ctypes 枚举顶层窗口，按标题关键字 + 浏览器进程认窗口），
     `stop.bat` 的 `:done` 里 `call :close_ui_windows`，`start.bat` 开新窗口前先清一遍。
     先发 `WM_CLOSE` 让它自己关（浏览器才有机会落盘），关不掉再强杀。
2. **界面设置重启后不再丢**
   - 真因：浏览器用 `--user-data-dir=<项目>\.browser`，localStorage 本来是持久的；
     但 stop.bat 用 `taskkill /f` 强杀浏览器，Chrome 来不及落盘
     （证据：`leveldb\000003.log` 的写入时间停在用户操作之前）。
   - 现在：`eg2-*` 的偏好双份存 —— 本地 localStorage（快、不闪）+ 服务端
     `GET/POST /api/ui-prefs`（写进 `index.db` 的 meta 表）。打开页面时回灌，
     本地独有的补传。`search.html` 里拦了 `Storage.prototype.setItem`，所以
     标签页/视图/排序/外部模型配置这些现有调用点**不用改**就都覆盖到了。
   - 折叠 key 也修了：原来取标题前 6 字，`已命名（3）` 带数量 → 命名一个人折叠状态就丢；
     现在数字被剥掉，人物页固定成 `eg2-pgfold-named` / `eg2-pgfold-unknown`。
     人物列表重渲染后也立刻恢复折叠态（原来要等 2.5 秒的轮询，看着像闪一下）。
3. **PDF 预览：按页文字 + 原版式出图 + 命中定位**
   - 背景：索引里存的是「各页文字拼成一整段」，页码在抽取阶段就丢了，表格版式更不在文字层里。
   - 后端（不重新索引，预览时现读）：
     `GET /api/preview/{id}/pdf-pages`（pypdf 按页给文字 + 告诉前端能不能出图）
     `GET /api/preview/{id}/pdf-page?page=N`（PyMuPDF 渲染成 PNG；没装返回 503 + 安装提示）
     `GET /api/preview/{id}/pdf-hits?q=`（PyMuPDF 文字层**按字面定位**：第几页 + 页内 0~1 比例坐标）
   - 前端：PDF 预览顶部一条模式栏 —— **内置查看器** / **按页文字** / **看原版式**。
     · 带着查询词打开时**默认进「看原版式」**：整页缩放（看全貌）+ **黄色框标出命中位置**
       （内置查看器的 PDF 是浏览器插件渲染的，外部没法在上面画框，所以标色只能在渲染图上）
     · 点页面图可切换「整页 ↔ 适宽」（适宽看清小字），选择记在 `eg2-pdf-fit`
     · 内置查看器地址带 `#page=N&zoom=page-fit`（实测 Chrome 认这两个片段，用户已确认跳页生效）
     · 按页文字：标「第 N / 总页」+「本页有 M 处」+ 命中词高亮 + 翻到别页时给「跳到命中页」
     · **语义命中**（页面上没有原词，例如搜「家谱」）会明确说明，不假装定位到了
     · 查询词从**当前所在的标签页**取（搜索页 `#q` / 知识库页 `#kb-q`）——
       之前只读 `#q`，在知识库提问后点来源时取到空串，表现就是「完全没反应」
   - 按位置定位很便宜：48 页的 PDF 全页扫一遍只要 0.03~0.6 秒。
   - ⚠ 一个坑：**从知识库「来源」列表点进来的 PDF，`item.kind` 传的是 `'other'`**
     （kb 那里构造 item 时按扩展名只区分了 image/other），所以 `openPreview` 里
     只按 `kind === 'pdf'` 判断就会绕过 PDF 预览那条路 —— 表现为没有模式栏、
     也不会定位。现在改成 `kind === 'pdf' || 路径以 .pdf 结尾`（`pdf_locate_test.mjs`
     第 6 组专门测这个场景）。
   - 依赖：`pymupdf` 已写进 `requirements.txt`；旧环境双击 `安装PDF原版式.bat` 补装。
4. **start.bat「服务启动失败或超时」误报 → 界面不打开（用户实测踩到）**
   - 现象：双击 search.bat 后只留两个黑框，浏览器窗口不出现；窗口里是 start.bat 的
     超时分支（打印日志最后 25 行 + `请按任意键继续`）。
   - 真因：`server.py` 是**模型加载完之后**才写 `run\server.pid`（实测 16:01:24），
     而 start.bat 的 `:still_alive` 会拿这个文件里的 pid 去 `tasklist` 查。
     上一个实例被 `taskkill` 强杀时没人清理 pid 文件 → 加载期间读到的是**旧 pid** →
     查不到 → 误判「服务已死」→ 第一次循环就跳超时，界面根本不打开。
   - 还有一层：start.bat 原来把 `call :kill_service_windows` 排在 `:is_healthy` **之前** ——
     服务本来好好开着，双击 search.bat 也会先被强杀（强杀又正好留下过期 pid）。
   - 修法：① 先查健康、确认没在跑再清遗留窗口；② 启动新服务前先删掉过期 pid 记录；
     ③ `:still_alive` 加注释说明「没有 pid 文件时应继续等」。
     验证：`run\test_start_bat.py` 做 A/B（同一场景跑原版和修好的版本），
     原版第一次判定就误判、修好的不再误判且会删掉过期 pid。
   - 另外给 `app\close_ui.py` 加了护栏：显式跳过控制台进程和标题带「服务窗口」的窗口，
     免得读不到进程名时把服务自己的黑框关掉（`run\test_close_ui.py` 已覆盖这条）。
   - `app\run_server.bat` 加了两行提示，说明这个黑框可以最小化、停止要双击 stop.bat。
5. **接入自建 Dify：外部知识库适配器**（用户最终目的：Dify 在服务器上、PC 不常开）
   - 关键约束（已查 Dify 官方文档核实）：**Dify 不接受外部向量** —— 导入文档就等于用它
     自己的模型重新切分+嵌入。所以走 Dify 的「外部知识库」：Dify 只来调检索，数据不动。

   - 密钥在 `config.ini` 的 `[dify] api_key`（本轮新加的段）。
   - `knowledge_id` 约定：`all`/空 = 全部知识库；数字 = 文件夹 id；别的词 = 路径关键词
     （如 `obsidian`）；匹配不到就退回全部（免得拼错就永远检不到东西）。

      `C:\WINDOWS\SYSTEM32\cmd` —— 顺着查发现**任务的动作本身就是 `sync_all.bat`** ✗：
      那是早先用 `schtasks /Create` 注册的（它只支持一个动作，所以当时用 .bat 把两步
      串起来），而 .bat 由 cmd.exe 执行 → 每跑一次必然闪一个黑框。
      后来 `setup_task.py` 重新注册时 `Register-ScheduledTask` 被系统拒绝
      （0x80041003 / 0x80070005），而它那条 schtasks 兜底又被 PowerShell 的退出码
      **误报成成功** ✗，所以旧任务一直没被换掉。
      修法：新增 `run\deploy\sync_all.py`（Python 启动器，串起两步同步，无 .bat 无 cmd）；
      `setup_task.py` 改为注册**单动作** `pythonw + sync_all.py`；
      `run\deploy\fix_task_action.py` 用"导出任务 XML → 只改 `<Command>`/`<Arguments>`
      → 导回"就地改掉已注册的任务（保留原有触发器：登录时 + 每 15 分钟）。
      ⚠ 两个新坑：① 任务 `Arguments` 必须用**绝对路径** —— "起始于"目录不一定生效，
      相对路径会变成"系统找不到指定的路径"，**任务触发了但脚本根本没跑**（日志里
      什么都没有）；② 判断"有没有开可见窗口"要看 `cmd` / `OpenConsole` /
      `WindowsTerminal` 的新增，`conhost` 单独新增只是 CREATE_NO_WINDOW 建的
      **隐藏**控制台，属正常现象。
      实测（触发任务并逐秒采样进程）：改前 `cmd+1 / conhost+2 / OpenConsole+1 /
      WindowsTerminal+1`；改后仅 `conhost+2`（隐藏），任务日志完整
      （sync_data 4s、sync_db 24s、退出码 0）。
10. **部署包 v2.0**：`docs\make_package.py` 起把 `run/deploy`（服务器部署 + 双向同步 +

## 开发纪律（血泪教训，务必遵守）

```
① .bat 必须 GBK 编码 + chcp 936，而且要 CRLF
   · 不能用编辑器/写文件工具直接改（会写成 UTF-8，cmd 在字节偏移处误解析）
   · 用 Python 读写：open(path, encoding='gbk', newline='')，写完统一成 CRLF
     （例子：run\patch_bats.py、run\make_install_pdf_bat.py）
   · 改完做一次空转解析测试（把关键变量指到不存在的路径，看它是否走到预期分支）
② 改 HTML 里的 JS 后，跑 run\check_js.py（script 配对 + 每块 node --check）
③ 字符串替换加 async 极其危险：
   · "function X(" → "async function X(" 如果 X 前面有注释，
     会变成 "async /* 注释 */ function X(" → 浏览器报 async is not defined
   · 先全部撤回，再只按 node 报错逐个补
④ 插代码时注意别吃掉原有的 <script> 标签（我犯过，导致整个页面瘫痪）
⑤ 改完必须：重启服务 → 用 /health 和 /search 验证 → 让用户强刷
⑥ 服务端接口改动后，browser 页面不用强刷（已加 no-cache 头）
⑦ Python 改完先 py_compile；前端改完跑 run\domtest 里的三套测试
   （cd 项目根目录 && node run\domtest\page_smoke.mjs）
⑧ 别用 PowerShell 做 UTF-8 文件的读改写往返（PS 5.1 默认按 GBK 读，会把中文注释写坏 —— 我踩过）
```

## 关键设计决定（不要改回去）

```
· 知识库检索必须用「黑名单」排除 image，不能用白名单
  （白名单会把 PDF 的 kind='pdf'、Excel 的 kind='xlsx' 一起排除）
· 专有名词（人名/编号）必须靠字面关键词匹配，不能只靠向量
· 关键词命中要**直接注入结果**并保底名额，不参与向量排序竞争
· 候选条目处理前必须先 sort（否则队尾的永远轮不到）
· caption 向量的 prompt 和维度必须和正文一致（Document + cfg.index_dim）
· 重新聚类会保留手动命名的脸（快照+强制归回）
· 界面偏好 = localStorage（快）+ 服务端 meta 表（防丢），两边都写
· PDF 页码/版式一律**预览时现读**，不进索引（否则要重建 4 万多个文件）
· 关界面窗口先 WM_CLOSE 再强杀（强杀会丢浏览器没落盘的数据）
· 界面布局：PDF 默认仍是内置查看器，按页/出图是「可选项」，别把默认换掉
```

## 沙箱里做不到的事（下一个会话不用重复试）

```
① 装包进 venv：装不了。fix-permissions.bat 把 venv 设成 Medium 完整性级别
   （防止低权限进程改解释器），沙箱是 Low → WinError 5。
   要让用户自己跑：安装PDF原版式.bat（或 setup.bat）。
② pip install 在沙箱里会失败/挂住：TMP/TEMP 必须指到项目内（.cache\tmp），
   就算指了，解包那一步也读不了自己的 .whl（Errno 13）。
   绕过办法：wheel 就是 zip，下载后直接 zipfile.extractall 到目标目录
   （例子：run\install_pymupdf_manual.py）。
③ 沙箱起不了 Chrome（headless 也不行）：crashpad OpenProcess 被拒 + IPC 受限，
   进程直接退出。→ 真浏览器验证只能让用户做；自己验证用 run\domtest（jsdom）。
④ 沙箱拉起的服务是 Low 完整性：/health 里 integrity=Low、desktop_ok=false，
   「定位文件 / 用系统程序打开」不可用（界面会显示⚠提示）。
   所以验证完要让用户 stop.bat → search.bat，换成正常权限的服务。
⑤ 关不了用户浏览器里的窗口：Low 进程给 Medium 窗口发消息会被拒（错误 5）。
   但 TerminateProcess 能成功 —— 这也是为什么「关窗口」的兜底要小心用。
```

## jsdom 测试的两个坑（写测试时会遇到）

```
· 每个 window.eval(块) 有自己的词法作用域：let/const 不跨块共享
  （真实浏览器里同一个全局环境是共享的）。
  → 所以别用 window.pvFile 去改脚本作用域变量，走真实入口（如 openPreview）
· jsdom 没实现 innerText / scrollIntoView，用 textContent，并在 dom_boot.mjs 里补空实现
```
