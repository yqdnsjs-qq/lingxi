# 宇之语·灵犀 v3.5 安装部署手册

> 适用版本：v3.5
> 覆盖：本机版（通用）、服务器版（Linux）
> 最后更新：2026-10-22

---

## 〇、先搞清楚你要装哪个

| 你要干什么 | 装哪个 |
|---|---|
| 自己电脑上用（管理员或普通用户都行） | **本机版**（通用，一个包） |
| 多人共用一台服务器，各自看各自的文件 | **服务器版** |
| 已经从 v3.0 / v2.x 装过了 | 看《升级部署手册-v3.5.md》 |

> **本机版是"通用版"**：装一次，谁登录都能用全部本机功能（建库/索引/打标/备份）。
> 管理员和普通用户的唯一区别：**能不能操作服务器**。详见 §1.4。

> **三者是同一份代码**，区别只在于配置和"是不是建库机"。
> 判断标准在代码里：`run/deploy/sync_db.py` 这个文件**在** → 建库机（本机版）；
> **不在** → 服务器版。所以**别手动复制这个文件**到服务器上。

## 一、本机版（通用）

### 1.1 环境要求

| 项 | 最低 | 推荐 |
|---|---|---|
| 系统 | Windows 10 64 位 | Windows 11 |
| 内存 | 8 GB | 16 GB 以上 |
| 硬盘 | 20 GB 可用 | 50 GB 以上（索引库会变大） |
| 显卡 | 不需要 | NVIDIA 显卡 6 GB 显存以上（快 10 倍） |

内部校验：Python 3.12、PyTorch、transformers 都装在包内 `venv\` 里，
**不动系统 Python、不改注册表、不改 PATH** ✓

### 1.2 安装

1. 把 zip 解压到一个**固定位置**，例如 `D:\灵犀\`
   - ⚠ 不要放在 OneDrive / 坚果云等同步盘里（索引库频繁写，同步盘会冲突）
   - ⚠ 路径里尽量不要有空格
2. 双击 **`setup.bat`**
   - 自动建 `venv\`、装依赖（约 10~30 分钟，看网速）
   - 中途问是否装 CUDA 版 PyTorch：有 N 卡选是
3. 双击 **`start.bat`**
   - 首次会下载嵌入模型（约 2 GB）到 `models\`
   - 加载完会自动打开浏览器

### 1.3 首次配置

1. 浏览器打开后，**创建管理员账号**（用户名 2~24 字，密码至少 6 位）
   - 第一个账号**自动是管理员**
2. 进「设置 → 模型与系统设置」，按需要调：
   - 「运行模式与设置」→ 运行设备（有显卡选 `cuda`）
   - 「向量维度」→ 推荐 256（只影响以后新建的文件夹）
3. 进「📁 文件夹」→ 添加要索引的目录 → 开始索引

### 1.4 通用版：管理员和普通用户有什么区别

**结论：本机上的功能一模一样，唯一区别是"能不能操作服务器"。**

| 能力 | 本机 · 管理员 | 本机 · 普通用户 |
|---|---|---|
| 建库、加/删文件夹、建索引 | **能** ✓ | **能** ✓ |
| 图片打标、OCR、人物命名 | **能** ✓ | **能** ✓ |
| 改模型/维度等本机设置 | **能** ✓ | **能** ✓ |
| 备份、还原、拍快照（本机数据） | **能** ✓ | **能** ✓ |
| 自己的 API / Dify 配置 | **能** ✓ | **能** ✓ |
| **服务器上的管理动作**（全站备份、改别人的文件夹、改全站设置、审批用户） | **能** ✓ | **不能** ✗ |
| 看到的数据 | 按归属：自己名下 + 共享的 | 同上（**不是"看全部"**） |

判据只有一条：**这台机器是不是他自己的电脑**（代码里看 `run/deploy/sync_db.py` 在不在）。

> 数据可见性由 `config.ini` 的 `[multi] local_strict` 控制：
> - `yes`（默认）：本机也按归属隔离 —— 普通用户只看自己名下 + 共享的
> - `no`：本机所有人都看到全部（适合"这台电脑就是我一个人的"）
>
> 注意这是**数据可见性**，不是功能开关。

### 1.5 界面长什么样（v3.5 的新结构）

顶部只有 **5 个主标签**，功能都按用途收进去了：

| 主标签 | 放什么 |
|---|---|
| 💬 聊天 | 会话、联网、接知识库、接 Dify、附件、导出 |
| 🔍 搜索 | 搜索框 + 结果 + 索引进度 |
| 📚 知识库 | 只查标了「知识库」的文件夹；可勾「☁ Dify 一起查」 |
| 📁 文件夹 | 已索引的文件夹、**默认排除目录**、索引统计 |
| ⚙ 设置 | 页内再分 4 类（见下） |

设置页的 4 类（按顺序）：

1. **🌐 服务器与共享**：服务器连接（账号+密码，验证身份）、上传到服务器、我的数据、共享给我的、隐私文件夹
2. **🧠 模型与系统设置**：运行模式与设置、显存控制、外部模型、Dify 知识库、图片打标、PDF 插图打标
3. **👤 人物命名**：人脸聚类、按人筛图、重新聚类/归类补全/同名去重/合并相似组/补提人脸
4. **💾 备份与恢复**：快照与异地副本、数据库备份、定时增量备份

> 二级标签的选中状态会记住；折叠过的卡片也会记住，重新打开还是原样。

### 1.6 给其他人开账号

管理员进「用户管理」（`/static/users.html`）：

| 想干什么 | 怎么做 |
|---|---|
| 直接给某人开号 | 「新建用户」→ 填用户名密码 → 创建（默认直接启用） |
| 让别人自己注册 | 打开「允许任何人自助注册」→ 对方注册 → 你点「审批通过」 |
| 不想让任何人注册 | 关掉那个开关（默认就是关的） |
| 给某人分配文件夹 | 「文件夹 → 归属」里改，或 `venv\Scripts\python.exe run\assign_owner.py --to <用户id>` |

### 1.7 用户自己改名 / 改密码

用户登录后打开 `/static/users.html`，顶部有「我的账号」：

- 改用户名：要填**当前密码**确认身份
- 改密码：要填**旧密码**
- 改完密码后，其它设备上的登录会失效（当前这台保留）

### 1.8 接服务器（v3.5 改成了"必须验证身份"）

「设置 → 服务器与共享 → 服务器连接」：

1. 填服务器地址（可填多个，逗号分隔，内网优先）：
   `http://192.168.1.10:8199, https://你的域名`
2. **填服务器上的账号和密码**（必填）
3. 点 **「保存并验证」**
   - 会真的拿这组账号密码去服务器登录一次
   - 成功才算连上，并显示：`本机 = 建库机 · 视图：个人版 / 本机登录：xxx（管理员）`
   - 同时记下"服务器上你是谁"，供「上传到服务器」显示身份用

> **为什么上传不用另填账号**：v3.5 起，「⬆ 上传到服务器」卡里**没有**账号密码输入框了 ——
> 上传身份、数据归属一律由这里的验证结果决定，避免有人临时换个账号乱传。
> 想换身份，就回这里重新验证。

### 1.9 Dify 知识库（个人 + 可共享）

「设置 → 模型与系统设置 → ☁ Dify 知识库」：

- 每个库填：地址（只到端口，`/v1` 会自动去掉）、知识库 ID（36 位 UUID）、API Key
- **默认只有你自己能用**；每个库下面可以选：`只有我` / `所有登录用户` / `指定的人`（填对方登录用户名，保存时校验，查无此人标红）
- 共享出去的是"能用它检索"，**密钥始终在你账号里**，对方界面看不到
- 别人共享给你的库，会以「🤝 别人共享给我的库」列在你卡片下面（只显示名字和来自谁）
- 聊天页勾「☁ Dify」、知识库问答页勾「☁ Dify 一起查」时生效

### 1.10 日常使用

| 操作 | 怎么做 |
|---|---|
| **启动（推荐）** | 双击 **`启动灵犀.vbs`** —— 全程**没有黑框**，服务在后台跑 |
| 启动（想看过程） | `start.bat`（会显示一个窗口，跑完自己关） |
| 停止 | `stop.bat`（黑框关不掉服务，要停就用它） |
| 重启 | `restart.bat` |
| 看状态 | `status.bat` |
| 备份数据库 | `backup.bat` |
| 从备份恢复 | `restore.bat` |

> [!tip] 为什么没有黑框了（v3.5.4 起）
> 以前 `start.bat` 会开一个"服务窗口"黑框，**一误关服务就断了**。现在改成隐藏启动
> （`app\run_server_hidden.vbs`）：
> - 没有任何命令行窗口，误关不到
> - 要停服务：双击 `stop.bat`（或界面里退出）
> - 想看启动过程/排错：直接双击 `start.bat`，行为和以前一样
>
> 建议把 `启动灵犀.vbs` **发送到桌面当快捷方式**，改名成「灵犀」，以后双击那一个就行。

### 1.11 配置说明（`config.ini`）

包里的 `config.ini` 已经**清空了所有敏感项**（API key、同步 token、Dify 密钥），
需要时自己填。常改的几项：

```ini
[server]
host = 127.0.0.1        # 只允许本机访问；要局域网访问改 0.0.0.0
port = 8199
open_browser = yes

[model]
device = auto           # auto / cuda / cpu
dtype = auto
modality = text_image   # 全模态很吃显存，按需改

[search]
index_dim = 256         # 只影响以后新建的文件夹

[multi]
local_strict = yes      # 通用版默认 yes：按归属隔离
allow_register = no     # 自助注册开关（界面上切也行，立即生效）

[sync]
server =                # 服务器地址（也能在界面上填，界面上填会做身份验证）
user =                  # 服务器账号
password =              # 服务器密码（界面上"保存并验证"后会写入）
token =                 # 验证时换到的会话令牌（自动写入，一般不用管）
```

改完**重启服务**生效（`restart.bat`）。

> `allow_register` 在界面上切换是**运行时生效**的（存在数据库 `meta` 表里）；
> 改 `config.ini` 只是改"默认值"，界面上的开关优先。

## 二、OCR 组件（可选，本机版）

### 先说结论

**OCR 不是必需的**。不装也能用灵犀 —— 只是：

- PDF 只能按**文件名**检索，不能提取正文
- 扫描件、截图里的文字提不出来
- 图片只能靠打标描述，不能 OCR

### 三个引擎，按需选一个

| 引擎 | 体积 | 显存 | 适合 |
|---|---|---|---|
| **RapidOCR**（推荐先用这个） | **0.26 GB** | 不占（纯 CPU） | 日常扫描件、截图、PDF 图片 |
| PP-OCRv6 | 3.8 GB | 要 GPU | 需要文字坐标、更高准确率 |
| MinerU | 11.6 GB | 要 GPU | 结构化 Markdown、表格、自动提图 |

> 三个引擎都跑在**独立环境**里（独立 venv 或完整运行时），通过子进程调用。
> 这么做是因为它们的依赖（paddle / onnxruntime）又大又重，混进主环境会把依赖搞乱，
> 而且显存要能独立回收。

### 装 RapidOCR（最简单，5 分钟）

1. 双击 **`install_ocr.bat`**
   - 自动建 `ocr-rapid\.venv\`、装 `rapidocr-onnxruntime`（约 260 MB）
   - 自动复制桥接脚本
   - 自动生成 `ocr-env.bat`（里面是引擎路径）
2. 重启灵犀（`stop.bat` → `start.bat`）
   - `start.bat` 已经会自动加载 `ocr-env.bat` ✓ 不用你手动改
3. 进「设置 → 模型与系统设置 → 图片打标 / OCR」，引擎应显示可用

**验证**：随便找个有文字的图片或扫描 PDF，索引后在预览里看有没有文字。

### 全部路径都可以改

引擎路径三级优先：**界面上填的（config.ini）→ 环境变量 `EG2_OCR_*` → 代码默认值**。
界面在「📁 文件夹 → ⚙ OCR 设置」里（折叠区「引擎路径」）。

| 环境变量 | 对应 |
|---|---|
| `EG2_OCR_RAPID_PY` / `EG2_OCR_RAPID_BRIDGE` | RapidOCR 的 python.exe / bridge.py |
| `EG2_OCR_PPOCR_PY` / `EG2_OCR_PPOCR_BRIDGE` | PP-OCRv6 的 python.exe / _lingxi_bridge.py |
| `EG2_OCR_MINERU_PY` / `EG2_OCR_MINERU_BRIDGE` / `EG2_OCR_MINERU_DIR` | MinerU 的 python / 提交脚本 / 根目录 |

### 服务器版要装 OCR 吗？

一般**不需要**：索引和 OCR 都在**本机版**做，服务器只负责搜索和展示。

## 三、服务器版（Linux）

### 3.1 环境要求

| 项 | 要求 |
|---|---|
| 系统 | Ubuntu 22.04 / 24.04（其他发行版需自行调整） |
| Python | 3.12（推荐用系统自带 + venv） |
| 内存 | 8 GB 以上 |
| 硬盘 | 30 GB 以上（索引库 + 模型） |
| 显卡 | 不需要（CPU 也能跑，慢） |

### 3.2 部署步骤

```bash
# ① 解压到固定位置
sudo mkdir -p /home/lingxi && cd /home/lingxi
unzip 灵犀-v3.5-服务器版.zip

# ② 建环境（约 10 分钟）
bash install.sh

# ③ 装成系统服务（开机自启 + 挂了自动重启）
sudo cp run/deploy/lingxi.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now lingxi

# ④ 等 30 秒让模型加载完，看状态
sleep 30
curl -s localhost:8199/health | head -c 100
```

`install.sh` 做的事：建 `venv/`、装 `requirements.txt`、下载模型、初始化索引库。
**它不会**建系统用户、不会改防火墙、不会装数据库。

### 3.3 首次配置

1. 浏览器打开 `http://<服务器IP>:8199`
   - 应该**直接跳到登录页**（不是嵌入调试页 ✓）
2. 首次会要求**创建管理员账号**
3. 进「用户管理」→ 给其他人开账号（或打开「允许自助注册」）

### 3.4 ⚠ 服务器版必须知道的五件事

**① 服务器没有建库能力**
包里**故意不含** `run/deploy/sync_db.py`。代码靠这个文件判断身份，
没有它 → 服务器模式：不能建库、不能打标、不能改模型。
**别手动把这个文件复制上去**。

**② 索引库和文件从本机同步上来**
在**本机版**上配好「服务器连接」（账号+密码，点「保存并验证」）→ 再「上传到服务器」。
v3.5 起上传身份由验证结果决定，不再能在上传卡里临时改账号。

**③ 强制登录**
服务器上 `EG2_ENFORCE_LOGIN=1` 已经写在 `lingxi.service` 里。
未登录访问任何业务接口都是 401；页面请求会跳登录页。

**④ 注册默认关闭**
`[multi] allow_register = no`。要开就在「用户管理 → 允许任何人自助注册」打开。

**⑤ 账号数量等敏感信息不外露**
外网访问时 `/api/auth/status` 返回的 `users` 是 `null`。

### 3.6 手动重启服务（NAS / 网络盘掉线时最常用）

**命令行（最稳，任何时候都能用）：**

```bash
cd /home/lingxi          # 你的安装目录
sudo systemctl restart lingxi      # 重启
sudo systemctl status lingxi       # 看状态
sudo journalctl -u lingxi -n 50 --no-pager   # 看日志
```

重启后**要等 25~40 秒**（模型要重新加载），再刷新页面。

**界面上也能重启**（v3.5.3 起，只有管理员看得见）：

「文件夹」页工具栏 → **♻ 重启服务** → 确认 → 页面会自动等它起来再刷新。

**网络盘（NAS）掉线、显示「目录不存在」时，按这个顺序处理：**

1. 先点 **🔄 重新检查目录**（不用等 30 秒轮询，立刻重查）
2. 还不行就 **♻ 重启服务**（或上面的 `systemctl restart`）—— NAS 重启后句柄失效，重启进程最干脆
3. 如果重启也不行，检查挂载点本身：

```bash
findmnt -T /mnt/nas_photo        # 看挂没挂上、挂的谁
sudo systemctl restart mnt-nas_photo.mount   # systemd 管的挂载
# 或者（NFS 常见）
sudo mount -o remount /mnt/nas_photo
```

> 小提示：服务器是 Linux，建库机上的 `\\NAS\share`、`D:\xxx` 这类 Windows 路径
> 在服务器上**本来就不存在** —— 界面会显示「· 本机路径」而不是「⚠ 目录不存在」，
> 那不是故障，别去救它。

### 3.7 服务器上的"公用模型"（普通用户免配置就能用）

服务器上部署的那台 **llama.cpp**（或任何**没填 API Key** 的外部模型）算"公共推理资源"：

| 谁配的 | 有没有 Key | 普通用户能用吗 |
|---|---|---|
| 管理员 | 没有 | **能**（公共）✓ |
| 管理员 | 有，选「所有登录用户」 | **能**（共享）✓ |
| 管理员 | 有，选「指定的人」并填了你的用户名 | **能** ✓ |
| 管理员 | 有，选「只有我」 | **不能** ✗ |
| 你自己 | 有没有都行 | 能（自己的）✓ |

所以在服务器上，普通用户进「聊天」和「知识库」时，下拉里**直接就有**服务器那台模型，
不用自己配；管理员那套带密钥的，只要没共享，普通用户看不到也用不了。
管理员在「设置 → 模型与系统设置 → 外部模型」里，每套 API 下面有一行
**「谁能用：只有我 / 所有登录用户 / 指定的人」**，改完立即生效。

### 3.8 外网访问（两个方案）

**方案 A：Cloudflare Tunnel（推荐，不用开端口）**

服务器上跑 cloudflared，隧道指向 `http://127.0.0.1:8199`。
优点：域名干净（`https://xxx.你的域名`）、自动 HTTPS、不开端口。
缺点：国内访问会被导到境外节点，首屏 8~9 秒（v3.5 已优化到约 3 秒的首屏渲染，
剩下的是链路延迟）。

**方案 B：公网 IP + 端口映射**

运营商封 80/443 时只能用非标准端口；可在 Cloudflare 用 Origin Rules 改回源端口。

### 3.7 性能（v3.5 做了什么）

- 前端轮询**按当前标签页门控**：不在「设置」页就不拉设置页的接口
- 慢接口降频：`/api/gpu/status`（约 8 秒）60 秒一次、`/api/faces/status` 只在「人物命名」组拉
- 实测：首屏「运行中」从 **14.3 秒 → 3.0 秒**，首屏接口数 18 → 12
- 带哈希的 JS/CSS 恢复**长缓存**（`immutable`），不再每次开页面重下 325 KB

## 四、常见问题

### Q1：`setup.bat` 卡在装依赖

- 检查网络，或改 `config.ini` 的 `[download] mirror = https://pypi.tuna.tsinghua.edu.cn/simple`
- 公司网络可能需要代理

### Q2：启动后浏览器打不开

1. 看 `logs\server.log` 最后 30 行
2. 确认 `run\server.pid` 存在
3. 端口被占 → 改 `config.ini` 的 `[server] port`

### Q3：模型加载失败 / 显存不足

- 改 `[model] device = cpu`（慢但一定能跑）
- 或 `modality = text`（只加载文本编码器，省一半显存）

### Q4：网络换地方后连不上服务器

本机版支持**多地址自适应**：

```ini
[sync]
server = http://192.168.1.10:8199, https://lingxi.example.com
```

按顺序探测，第一个通的就用 —— 在家走内网、出门走域名 ✓

### Q5：页面改了但浏览器还是旧的

按 **Ctrl + F5** 强制刷新。v3.5 起如果浏览器还引用着已被替换的旧静态文件，
服务器会返回一段"自动刷新一次"的脚本，不用手动处理。

### Q6：服务器上 `/docs` 打不开

**正常**。服务器版关掉了接口文档（`/docs`、`/redoc`、`/openapi.json` 都 404）。
本机版仍然是开的（开发调试用）。

### Q7：点「保存并验证」提示"账号或密码不对"

- 确认填的是**服务器上**的账号（不是本机账号）
- 确认服务器上这个账号是 `active` 状态
- 地址只填到端口，别带 `/v1`（Dify 的地址才有 `/v1` 的说法，这里是灵犀自己的）

### Q8：Dify 勾了但检索不到

- 地址只填到端口，如 `http://192.168.1.30:8080`
- 知识库 ID 必须是**完整 36 位 UUID**（少几位会一直 404，界面现在会直接提示"少了多少位"）
- 别人共享给你的库，要在`设置 → 服务器与共享/Dify` 卡片下方确认能看到它

## 六、安全建议

| 项 | 建议 |
|---|---|
| 管理员密码 | 别用弱密码；管理员能删数据 |
