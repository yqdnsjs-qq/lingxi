# 多用户（注册 / 各自使用）设计方案

> 版本：v2.1 草案　｜　依据：2026-10-16 与项目主的确认（下方"已定方案"）

## 0. 已定的四件事（项目主确认）

| 议题 | 决定 |
|---|---|
| 数据怎么分 | **共享库**（现有 43819 个文件那套）对普通用户**只读**；每人另有**私有文件夹**；**管理员可见全部** |
| 账号怎么来 | **管理员建号** ＋ **自助注册（需管理员审批）**，两种都要 |
| 普通用户能做什么 | **能加文件夹，但"建索引"要管理员批准** |
| 安全 | 先 **HTTP + 密码哈希**（不做 TLS；密码在局域网内明文，别用重要密码） |

**架构定位（最关键的一条）**：
**各自本机版为主** —— 每个人在自己电脑上建库（各自有显卡），然后**各自把自己的数据同步进服务器**；
**服务器主要承担问答**（偶尔各自改动）。**共享库由管理员同步**。

### 追加的四条（2026-10-16 项目主补充）

| 议题 | 决定 | 对设计的影响 |
|---|---|---|
| 共享库要**分组** | 43819 个文件里**有些共享、有些私有**，要能设置，**在管理界面自己选** | `folders` 加 `visibility`（`private`=只自己 / `shared`=所有登录用户可见）+ 例外用 `folder_acl(folder_id, user_id, can_read)` 指定给某些人；管理员界面按文件夹勾选 |
| 人物命名 | **大家都能看到** | 共享库的 people 对普通用户**只读可见**（不隐藏） |
| 对话历史 | **服务器按人存一份** | 新增 `chat_history(id, user_id, ts, q, answer, sources_json, engine, elapsed)`；界面按人读取，管理员可清理 |
| 现有库归属 | **管理员同步维护** | 现有 43819 文件升级后 `owner_id=0`；默认 `visibility='shared'`，由管理员按文件夹改成 `private` |

## 1. 角色与权限矩阵

| 能力 | 管理员 | 普通用户 | 说明 |
|---|---|---|---|
| 搜索 / 问答 | ✓ | ✓ | 共享库 + 自己的私有文件夹 |
| 看共享库内容 | ✓ | ✓（**只读**） | 不能改共享库的文件夹配置 |
| 加/删自己的文件夹 | ✓ | ✓ | 加完是「待批准」状态 |
| 触发/批准建索引 | ✓ | ✗（只能申请） | 索引很吃 CPU，集中在管理员手里 |
| 把本机索引同步上来 | ✓ | ✓ | **只同步自己名下的文件夹** |
| 人物命名（people） | ✓ | 仅自己文件夹内的 | 共享库的人名只读 |
| 全局设置（设备/模态/端口/模型） | ✓ | ✗ | 普通用户看不到那张卡片 |
| 切换对话模型 / 卸下模型 | ✓ | ✗ | 影响所有人 |
| 用户管理（启用/禁用/改角色/重置密码） | ✓ | ✗ | |

## 2. 数据模型（在现有 SQLite 上加列，尽量不动结构）

```
users            id, name(唯一), pwd_hash, role('admin'|'user'), state('active'|'pending'|'disabled'),
                 created_at, last_login
folders          + owner_id INTEGER   -- 0=共享库（管理员维护），>0=该用户私有
                 + index_state TEXT   -- 'draft'|'pending'|'building'|'ready'   （审批用）
files            + owner_id INTEGER   -- 冗余自 folders，便于按人过滤（索引时写入）
meta             -- 键名带用户前缀：u<id>.eg2-*（界面偏好按人分开）
sessions         token, user_id, created_at, expires_at, ip, ua   （或统一放 meta）
audit            ts, user_id, action, detail        （审批/建索引/登录，便于追责）
```

- **共享库 = `owner_id = 0`**：由管理员的本机版建库并同步上来；普通用户只读。
- **普通用户新增文件夹 → `index_state='pending'`** → 管理员批准后置 `'building'`/`'ready'`。
- 迁移：启动时执行幂等的 `ALTER TABLE ... ADD COLUMN`（用 `PRAGMA table_info` 判断是否存在）；
  现有数据一律 `owner_id = 0`（即全部归共享库）—— **老用户升级后表现不变**。

## 3. 鉴权与会话

- 密码：`hashlib.pbkdf2_hmac('sha256', pwd, salt, 200_000)`，盐每人随机；库里只存 `salt$hash`（**零新依赖**）。
- 会话：登录成功发 **HttpOnly + SameSite=Lax Cookie**，令牌随机 32 字节，存 `sessions` 表，默认 7 天。
- **CSRF**：所有写操作要求自定义头 `X-EG2-CSRF: 1`（跨站表单带不上自定义头）；登录/注册接口再校 `Origin`。
- 登录限速：同一 IP + 用户名，5 分钟内失败 5 次锁 5 分钟（记 `audit`）。
- 首次启动：`users` 为空时，**所有接口放行**并只显示「创建管理员」页；
  建完管理员立刻全面生效（避免升级后把自己锁在外面）。
- 未登录访问：返回 401 + 前端跳登录页（数据接口一律鉴权；`/health`、静态资源、`/search` 页面本身除外）。

## 4. 同步协议（**必须重做**，这是多人的前提）

**现状（单人可用、多人会互相覆盖 ✗）**：
生成整库快照 → `scp` 覆盖服务器 `index.db` → 热重载/重启。

**新设计：按用户推送"子集库" + 服务器合并**

```
① 用户在自己的本机版上索引自己的文件夹（本机有显卡，快）
② 客户端生成**只含自己名下文件夹**的子集库：
     - files/chunks/faces/people/folders 里 owner_id = 我的行
     - 带上我的 figure 命名
③ 上传子集库（scp 到 ~/lingxi/data/index/incoming/<user>-<ts>.db）
④ 服务器用 SQLite ATTACH + INSERT OR REPLACE 合并进主库（按主键/路径去重）
     - 只动 owner_id = 我的行，碰不到别人的和共享库
     - 合并完删掉子集库；**不需要删主库、不需要重启**（热重载那套因此可以退休）
⑤ 返回合并统计（新增/更新/删除各多少），客户端写日志
```

要点：
- **不再整库替换** → 多人能并存，且服务器随时可问答（不中断）。
- **`users` 表必须一并做并集合并**（按 `name` 去重，谁的密码哈希都不覆盖；同名冲突记录进 audit）。
  否则会出现：某人在**服务器**自助注册 → 管理员从本机推一次库 → 那个账号被冲掉 ✗。
- **`sessions` 与 `audit` 不同步** —— 会话是"本机/本服务器"的本地状态，同步会串号 ✗。
- **P4 之前的行为约束（重要）**：现在的同步仍是"本机整库覆盖服务器"，
  所以**账号一律在本机（PC）建** —— 在服务器上建的用户/管理员会被下一次推送冲掉 ✗。
  等 P4 的并集合并上线后，两边都能建。
- 删除要显式：客户端算出"我的文件夹里已消失的路径"，随子集库带一张 `deleted` 表（或 JSON），
  服务器只删这些路径且限定 `owner_id = 我`。
- 共享库由**管理员**用同一条通道推送（`owner_id = 0`）。
- 兼容：`sync_db.py` 增加 `--user <名字>`；不带参数时仍按"管理员 + 共享库"跑（老的定时任务不受影响）。
- 冲突策略：同一路径只有它的 owner 能写 → 天然无冲突；共享库只有管理员能写。

## 5. 前端改动

- 新增**登录/注册页**（未登录时替换整个界面）；首次启动是**创建管理员**页。
- 顶栏加**用户菜单**：当前用户、我的文件夹、退出。
- 「文件夹」页：显示归属（共享 / 我的）、状态（待批准 / 已就绪 / 索引中），普通用户看到「申请建索引」按钮。
- 「设置」页：普通用户**看不到**全局设置卡片与对话模型卡片（后端也拦，不只是藏）。
- 「人物」页：普通用户默认只看自己文件夹内的人；共享库的人名只读。

| 阶段 | 内容 | 验收 |
|---|---|---|

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 升级后把自己锁在外面 | 首启（users 空）放行 + 创建管理员页；改完立刻生效并提示 |
| 迁移改坏现有库 | 启动前自动备份（已有 `backup.bat` / 服务器快照）；迁移幂等；列全部可加不可减 |
| 多人问答把 CPU 打满 | 对话模型只有 2 个并发槽 → 排队；界面上显示"前面还有 N 个问题" |
| 普通用户偷偷建索引 | 后端校验角色（不只藏按钮）；审计表记录 |
| 同步合并写坏主库 | 合并放在事务里；合并前自动备份主库；子集库作为凭据保留 7 天 |
| 密码明文过网 | 文档显著提示别用重要密码；计划支持自签 HTTPS（另议） |
| 老的单人同步脚本 | `sync_data.py` 不受影响；`sync_db.py` 不带 `--user` 时行为与现在一致 |
