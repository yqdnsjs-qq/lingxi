# 我把 6 万个文件、121 GB 的资料，塞进了自己电脑里的一个"能对话的搜索框"

先说三个我自己的真实场景。

**场景一**：我要找去年那份差旅报销的发票。我记得是 PDF，记得内容是报销，但文件名？想不起来。于是打开资源管理器，一层一层翻。

**场景二**：我想知道"上次那个方案里，预算到底是怎么定的"。答案可能在一份 Word、一份 PDF、一张会议白板的照片里。我得挨个打开看。

**场景三**：家里/公司有台服务器，资料想几个人共用，但各自看各自的，别互相翻。

这三件事，以前分别要用三个东西解决：搜索、笔记、网盘。现在我用同一个项目解决了——它叫**宇之语·灵犀**，是一个跑在自己电脑（或自己服务器）上的**本地知识库**。

## 一、找文件：把"记忆"换成"提问"

传统搜索匹配的是**文件名**。可你脑子里记的是**意思**。

所以它换了个做法：不匹配字符，而是理解语义。

| 你想找的 | 你直接打 |
|---|---|
| 去年那份差旅报销的发票 | `去年的差旅报销发票` |
| 讲极光成因的资料 | `极光是怎么形成的` |
| 蓝色圆形的产品配图 | `蓝色圆形的产品图` |
| 算个税的脚本 | `计算个人所得税的代码` |

不用记文件名、不用猜扩展名、不用回忆在哪个盘。

而且它**认得图片**——你说"蓝色圆形"，它能把符合描述的图捞出来；你说"一张表格截图"，它也认。这是文件名搜索永远做不到的。

背后是 Google 的 `embeddinggemma-2`（7 亿参数级别的嵌入模型），把文字、图片都变成同一套"语义坐标"，搜的时候找距离最近的。

**顺序、用词、语序都不重要，意思对就行。**

【图：搜索界面 + 结果高亮】

每个文件夹还能有自己的策略：文档目录只做文字（最快）、素材目录文字+图片、安装包目录只索引文件名（秒级）。搜索是统一入口，不同模式的结果混在一起按相关度排序，每条都标着来自哪种模式的文件夹。

## 二、问资料：它不只是搜索框，还能对话

搜到之后，你多半还有下一句："那到底怎么说的？"

所以它把检索接进了聊天：**先在你自己库里找相关片段，再让模型基于片段回答，并且标出引用来源**。

```
你：报销上限是多少？
它：根据《差旅管理制度》第 3 节，一线城市住宿上限 600 元/晚 [1]，
    交通费据实报销 [2]。
    [1] 差旅管理制度.pdf · 第 3 节
    [2] 报销流程说明.docx · 第 2 段
```

回答里的 `[1] [2]` 点一下就能跳到那段原文——**不信的话，你自己去核对**。这一点很重要：AI 说的每句话都能溯源，才敢用在工作上。

还能接 **Dify**：如果你公司里已经在用 Dify 建知识库，可以把它一起接进来。提问时勾一下「☁ Dify 一起查」，本地资料标 `[1]`，Dify 资料标 `[D1]`，两套来源分得清清楚楚。

> 顺带说一句：Dify 的配置**默认只有你自己能用**。想给别人用，得你自己在每个库下面选「所有登录用户」或「指定的人」。密钥始终留在你的账号里，对方只拿到"能用它回答"这个权限。

## 三、几个人共用一台服务器：各看各的，边界清楚

一个人用够了，很容易想到：能不能放服务器上，让家里人/同事一起用？

可以，而且边界做得比较死：

- **归属**：每个文件夹有主人。普通用户只看得到自己名下的 + 别人共享给他的
- **共享**：可以共享给所有人，也可以点名给某几个人
- **服务器不建库**：索引和打标在你这台"建库机"上做，做完了**上传**到服务器，服务器只负责搜和答
- **上传身份不能临时改**：先在「服务器连接」里填账号 + 密码点「保存并验证」，验证通过才记录"你在服务器上是哪位"；「上传到服务器」那张卡里**没有**账号密码框——身份只认验证过的那一组，防止有人临时换个身份乱传

我这次实测的一组数字（跑在自己这台机器上，不是宣传口径）：

- 索引：**57,761 个文件 / 62,824 个片段 / 121.02 GB / 19 个文件夹**
- 人脸聚类出 **3,403 个人物**，可以按人筛图、给人物命名
- 首屏「运行中」从 **14.3 秒压到 3.0 秒**（把后台轮询改成"只在当前标签页跑"）

## 四、为什么敢把合同和财务资料放进去

**因为它们一步都没离开你的机器。**

- 文件和向量都存在本地（`data/index/index.db`）
- 模型跑在你自己显卡上（没有独显用 CPU 也能跑，就是慢点）
- 不传云端、不需要账号、**断网也能搜**
- 整个程序就在一个文件夹里：不改注册表、不装系统服务、不动 PATH。不想要了，删文件夹就干净了

对**合同、财务报表、客户资料、病历**这类"传上去就是事故"的东西，这一点是刚需。

## 五、一些"用起来才会在意"的细节

这些不是功能列表，是踩过坑之后补的：

- **断点续传**：模型下载断了，重跑 `setup.bat` 接着下
- **数据安全阀**：移动硬盘/网络共享扫到一半掉线，它**不会**误判"文件都被删了"而清空索引，会跳过并提示
- **坏文件不连累别人**：一张图解码失败，只有它被跳过并写明原因，同批其它照常入库
- **旧页面自动恢复**：浏览器还引用着已被替换的旧脚本时，服务器会返回一段"自动刷新一次"的脚本，不用你手动折腾
- **一键自检 / 备份 / 恢复**：`selftest.bat`、`backup.bat`、`restore.bat`，服务开着也能备

## 六、谁适合，谁可以不用

**特别适合：**

- 电脑里存了几万份文件，靠记忆和肉眼在找
- 有大量素材（图片、截图、设计稿），想按画面内容找
- 有**不能上传云端**的敏感资料，但想要智能搜索
- 家里/小团队有台能常开的机器，想共用资料又不想互相翻

**可能不需要：**

- 只想纯文件名匹配 → 用 Everything 更快更轻
- 文件基本都在网盘里 → 网盘自带搜索可能够用
- 机器只有 4 GB 内存又没独显 → 能跑，但会慢

## 七、怎么装（大概 30 分钟，25 分钟在下载）

```bat
:: 1. 装 Python 3.12（勾选 Add python.exe to PATH）
:: 2. 解压到纯英文路径，例如 D:\lingxi
:: 3. 双击 setup.bat        ← 建环境、装依赖、下模型（约 2 GB）
:: 4. 双击 start.bat        ← 浏览器自动打开
```

就这四步，中间不用敲命令。

装完第一件事：**把那几个"每次找东西都要翻半天"的目录加进去**，选个模式，剩下的它自己扫。

之后你会发现，回忆文件叫什么名字这件事，慢慢就不需要了。
