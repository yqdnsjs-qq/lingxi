# 宇之语·灵犀 · 部署手册

> 这份手册只讲「怎么装、怎么配、怎么升、出问题怎么查」，不含任何具体机器的路径、IP、账号。
> 文中 `<安装目录>`、`<服务器地址>`、`<端口>` 都要换成你自己的值，默认端口 **8199**。

## 一、两种部署形态

| 形态 | 适合 | 安装包 |
|---|---|---|
| Windows 本机版 | 一台电脑自己用，资料在本机/网络盘 | `lingxi-<版本>-setup.exe`（安装升级二合一） |
| Linux 服务器版 | 多人访问、长期在线、走 systemd | `lingxi-<版本>-server.zip` |

两种形态共用同一套代码与数据库格式，区别只在启动方式和依赖安装。

### 运行环境

- Python **3.12**（3.11 也可以，3.13 未验证）
- 内存：只跑检索 **4 GB** 起；要本地跑对话模型再按模型大小加
- 磁盘：程序约 50 MB；索引库随文件量增长（10 万文件约 0.5 GB）
- 嵌入模型：默认 `google/embeddinggemma-2`，首次启动会从 `models/` 目录加载；
  没有就自动下载（需要能访问 HuggingFace 或镜像）

## 二、Windows 本机部署

### 1. 安装

1. 把 `lingxi-<版本>-setup.exe` 放到你想安装的目录（安装包所在目录就是安装目录）
2. 双击运行，看到 `完成：v<旧> → v<新>` 或 `完成：v<版本>` 即结束
3. 浏览器会自动打开 `http://127.0.0.1:8199/static/search.html`

安装包做的事：

| 步骤 | 说明 |
|---|---|
| 停旧服务 | `POST /admin/shutdown`，轮询端口，兜底按命令行结束 `python.exe` |
| 备份旧程序 | `backups\upgrade-v<旧版本>-<时间>.zip`（只含 `app\`、`config.ini`、`VERSION`） |
| 覆盖程序 | `app\ run\ docs\` 与根文件；**不动** `data\ models\ venv\ config.ini logs\ backups\` |
| 首次安装 | 目录里没有 `config.ini` 就用包内模板生成（端口 8199） |
| 依赖 | `requirements.txt` 变了才 `pip install` |
| 启动 | `start.bat`（加 `--no-start` 只装不起） |

### 2. 目录结构

```text
<安装目录>\
├── app\              程序（升级时整体覆盖）
├── run\              运维脚本（部署、备份、重建索引…）
├── docs\             文档
├── data\             数据（升级不覆盖）
│   └── index\
│       ├── index.db  主库
│       └── kb\       分库（4.0 起，一个知识库一个 .db）
├── models\           模型（升级不覆盖）
├── venv\             Python 虚拟环境
├── config.ini        配置（升级不覆盖）
├── VERSION           当前版本
├── start.bat         启动
└── stop.bat          停止
```

### 3. 启停

```bat
start.bat          :: 前台窗口跑，关窗口即停
stop.bat           :: 优雅停止（走 /admin/shutdown）
```

想开机自启：把 `start.bat` 的快捷方式放进
`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup`。

### 4. 换端口

改 `config.ini`：

```ini
[server]
port = 8199
```

改完重启；防火墙放行同一个端口。

## 三、Linux 服务器部署

### 1. 准备

```bash
sudo apt install -y python3.12 python3.12-venv unzip
sudo useradd -m -s /bin/bash lingxi        # 用专用账号跑
```

### 2. 解包

```bash
sudo -u lingxi -s /bin/bash
cd /home/lingxi
unzip /tmp/lingxi-<版本>-server.zip -d lingxi-app     # 解到临时目录看结构
# 真正安装：把 app/ run/ docs/ requirements.txt 铺进 <安装目录>
cp -a lingxi-app/app lingxi-app/run lingxi-app/docs lingxi-app/requirements.txt <安装目录>/
cp lingxi-app/config.example.ini <安装目录>/config.ini   # 不要把包里自带的 config.ini 直接盖到已有安装
```

> **已有安装升级时**：只覆盖 `app/`、`run/`、`docs/`、`requirements.txt`，
> 千万不要覆盖 `config.ini`、`data/`、`models/`、`venv/`。

### 3. 依赖

```bash
cd <安装目录>
python3.12 -m venv venv
venv/bin/pip install -U pip
venv/bin/pip install -r requirements.txt
```

CPU 机器装 CPU 版 torch 即可（`pip install torch --index-url https://download.pytorch.org/whl/cpu`）；
有显卡再按 CUDA 版本装。

### 4. systemd

`/etc/systemd/system/lingxi.service`：

```ini
[Unit]
Description=Lingxi
After=network-online.target

[Service]
Type=simple
User=lingxi
WorkingDirectory=<安装目录>
ExecStart=<安装目录>/venv/bin/python -u app/server.py
Restart=always
RestartSec=5
# 需要强制登录时打开：
# Environment=EG2_ENFORCE_LOGIN=1

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now lingxi
sudo systemctl status lingxi --no-pager
```

### 5. 验收

```bash
curl -s http://127.0.0.1:8199/health
# {"status":"ok","version":"…","model_ready":true,...}
```

第一次启动要加载嵌入模型，CPU 上 **40~120 秒**；`model_ready` 变 `true` 再用。

### 6. 反向代理（可选）

前面挂 Nginx 时记得：

```nginx
location / {
    proxy_pass http://127.0.0.1:8199;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_buffering off;          # 问答是流式，别缓冲
    proxy_read_timeout 300s;
}
```

## 四、配置项（config.ini）

| 段 | 关键项 | 说明 |
|---|---|---|
| `[server]` | `host` / `port` | 监听地址与端口；对外只建议 `127.0.0.1` + 反代 |
| `[model]` | `name` / `local_dir` / `device` | 嵌入模型；`device` 可 `cuda` / `cpu` |
| `[search]` | `top_k` / `min_score` | 默认返回条数与相似度门槛 |
| `[chat]` | `model_dir` / `max_new_tokens` | 本机对话模型（可选） |
| `[sync]` | `token` / `password` | 多机同步凭据，**不要提交到仓库** |
| `[dify]` | `base_url` / `api_key` | 接 Dify 外部知识库（可选） |
| `[ocr]` | `engine` / `mineru_*` | OCR 引擎（ppocr / mineru / mineru4 / rapid） |
| `[backup]` | `keep` / `hours` | 定时备份份数与间隔 |

改完都要**重启服务**才生效。

## 五、升级

### Windows

双击新的 `lingxi-<新版本>-setup.exe` 即可（见第二章）。

### Linux

```bash
sudo systemctl stop lingxi
cp -a <安装目录>/data/index/index.db <安装目录>/backups/index-pre-upgrade.db   # 整库冷备
# 覆盖 app/ run/ docs/ requirements.txt（保留 config.ini / data / models / venv）
sudo systemctl start lingxi
sleep 60
curl -s http://127.0.0.1:8199/health
```

升级前把旧 `app/`、`config.ini`、`VERSION` 打个包，回退时解回去再重启即可。

> 3.5.x → 4.0 没有数据库结构破坏性变更；4.0 新增的「知识库分库」是**可选**的，
> 不分库就继续用默认库，行为与 3.5 一致。

## 六、数据、备份与迁移

- 主库：`data/index/index.db`（SQLite，单文件，可以直接拷走）
- 分库：`data/index/kb/*.db`
- 增量备份：`venv/bin/python app/dbbackup.py save "说明"`，存到 `backups/db/`
- 整库迁移：停服务 → 拷 `data/index/` → 起服务
- 索引重建：`venv/bin/python run/build_name_fts.py --force`（文件名索引）、
  页面上「重建向量矩阵」按钮（向量）

## 七、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `/health` 一直 `model_ready:false` | 模型还在加载（CPU 上要 1~2 分钟） | 等；看日志有没有下载失败 |
| 页面 401 / 跳登录 | 开了强制登录（`EG2_ENFORCE_LOGIN=1`） | 登录一次，会话默认 7 天 |
| 端口被占 | 旧进程没退干净 | `netstat -ano \| findstr :8199`，结束对应 PID |
| 网络盘文件「定位不了」 | 服务器上的挂载路径与库里存的不一致 | `app/remap_paths.py --old <旧前缀> --new <新前缀> --apply`（先停服务） |
| 搜不到刚加的文件 | 该文件夹还没建索引 | 文件夹页面点「重建」或等定时任务 |
| 问答报「模型不属于你」 | 外部模型配置改过、下标对不上 | 设置里重新选一次模型 |

## 八、卸载

- Windows：停服务 → 删安装目录（`data` 里是你的资料，确认后再删）
- Linux：`sudo systemctl disable --now lingxi` → 删 unit 文件 → 删安装目录与专用账号

## 九、版本与发布

- 版本号在 `app/version.py` 的 `VERSION` / `BUILD`
- 发布产物：Windows 安装升级包、Linux 服务器版、升级包
- 升级包只替换程序，不碰数据
