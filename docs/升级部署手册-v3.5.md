# 宇之语·灵犀 升级部署手册（v3.0 / v2.x → v3.5）

> 适用：**已经装过 v3.0（或 v2.x）**，要升到 v3.5
> 全新安装请看《安装部署手册-v3.5.md》
> 最后更新：2026-10-22

---

## 〇、升级前必读

### 0.1 这次升级改了什么（按影响排序）

| 变化 | 对你的影响 |
|---|---|
| **界面重整：5 个主标签** | 聊天 / 搜索 / 知识库 / 文件夹 / 设置。原来的「人物」并进「设置 → 人物命名」；「检索与索引」的内容挪到「文件夹」页 |
| **设置页内分 4 类** | 服务器与共享 / 模型与系统设置 / 人物命名 / 备份与恢复（二级标签，顺序固定） |
| **轮询按页门控** | 首屏「运行中」从 14.3 秒降到 3.0 秒；不在设置页就不拉设置页的接口 |
| **Dify 改为"个人 + 可共享"** | 默认只有自己能用；每个库可选「只有我 / 所有登录用户 / 指定的人」。**密钥永不下发给别人** |
| **知识库问答页支持合并 Dify** | 多一个「☁ Dify 一起查」开关；回答里本库是 `[1]`，Dify 是 `[D1]` |
| **服务器连接必须验证身份** | 账号 + 密码必填，「保存并验证」会真的登录一次服务器，并显示"本机 / 服务器"两种身份 |
| **上传到服务器不再能填账号** | 身份只认「服务器连接」里验证过的那一组（防止临时换身份乱传） |
| **修 4 个 bug** | 见 0.3 |

> **没有数据库结构变化**：新字段全在 `user_prefs` 的 JSON 值里
> （Dify 每条多 `share` / `share_to`，老记录没这两个字段 = 私有），
> 不用跑 SQL、不用迁移 ✓

### 0.2 ⚠ 三个绝对不要做的事

1. **不要删掉 `data/index/index.db`** —— 那是全部索引，重建要几小时到几天
2. **不要覆盖 `config.ini`** —— 升级包不含它，但如果你手动复制整个文件夹就会覆盖
3. **不要把 `run/deploy/sync_db.py` 复制到服务器** —— 它是"本机/服务器"的身份标记

### 0.3 这一版修的 4 个 bug（你可能会遇到的现象）

| 现象 | 原因 | 现在 |
|---|---|---|
| 填了服务器账号密码也提示"账号或密码不对" | 同步客户端发的是 `password`，登录接口收的是 `pwd` → 密码永远没送到服务器 | 已修（两个字段都发） |
| 页面弹出「脚本错误：Unexpected end of input」 | 浏览器还引用着已被替换的旧 `app.<哈希>.js`，服务器回空 404 | 旧哈希文件现在返回一段"自动刷新一次"的脚本 |
| 每次打开页面都把 325 KB 的 JS 重下一遍 | 心跳中间件把哈希文件的 `immutable` 缓存头盖成了 `no-cache` | 已修，哈希文件恢复长缓存 |
| 预览 Markdown 时满屏 404 + 语法错误 | 图片 `onerror` 里用 `JSON.stringify` 拼进了双引号属性，属性被截断 | 已修（改用 `this.title`） |
| 普通用户登录服务器后，聊天/知识库**选不到服务器那台 llama.cpp**；管理员配的模型也看不见 | 模型配置存在**管理员自己的偏好**里，别人的查询只看"全局默认 + 自己那份"；而"没密钥 = 公共资源"的规则只在单条上判断，整份列表根本传不过来 | 已修：`app/apimodels.py` 统一算"你能用的"——自己的全部 + 别人的**无密钥（公共）**/共享给我的 |
| 管理员的「共享模型」按钮点不动 | ① 按钮绑的弹窗要先异步取用户列表，**接口路径写错（404）**且拿不到结果；② 按钮还藏在折叠卡片里 | 已修：共享改成卡片内一行「谁能用 + 用户名」，改完即存；密钥不外泄 |

## 一、Windows 本机版升级

### 1.1 升级前（5 分钟，必做）

```bat
:: ① 停服务
stop.bat

:: ② 备份数据库（增量，很快）
venv\Scripts\python.exe app\dbbackup.py save "升级前"

:: ③ 备份配置
copy config.ini config.ini.bak-升级前
```

**如果没停服务就备份**：数据库是 WAL 模式，热备份可能拿到不一致的页。
`dbbackup.py` 内部会处理，但**停服务最保险**。

### 1.2 升级

1. 解压 `灵犀-v3.5-升级包.zip`
2. 把里面的 **`app\` 整个文件夹**覆盖到原目录（选"替换目标中的文件"）
3. **确认这几样没被动过**：
   - `config.ini`（你的配置）
   - `data\`（索引库）
   - `models\`（模型）
   - `venv\`（运行环境）
4. 如果有 `.bat` 脚本更新（`start.bat` / `stop.bat`），也一并覆盖

> 升级包只含 `app/` + 文档，不含 `venv/`、`data/`、`models/`、`config.ini` ✓

### 1.3 升级后

```bat
start.bat
```

1. 浏览器打开后 **Ctrl + F5 强制刷新**（前端文件名带哈希，必须强刷一次）
2. 登录，检查这几件事：
   - 顶部只有 5 个标签（聊天 / 搜索 / 知识库 / 文件夹 / 设置）
   - 「📁 文件夹」里能看到文件夹列表 + 默认排除目录 + 索引统计
   - 「⚙ 设置」的 4 个二级标签都能点开
   - 搜索能返回结果
   - 「设置 → 人物命名」能看到人脸

### 1.4 升级后的身份变化

- **本机**：还是个人版，功能全开（和 v3.0 一样）
- **服务器连接**：以前存的地址/账号仍然在，但 v3.5 要求**点一次「保存并验证」**——
  验证通过才会记录"服务器上你是谁"，也才会把凭据写全（密码 + 令牌）
- **上传到服务器**：第一次用之前，先去「服务器连接」验证一次，否则会提示"还没验证服务器身份"

### 1.5 Dify 升级注意

v3.0 里填过的 Dify 库会自动继承过来，**默认全部是"只有我"**（跟以前一样安全）。
想让别人也能用：去「设置 → 模型与系统设置 → ☁ Dify 知识库」，每个库下面选
「所有登录用户」或「指定的人」。

> v3.0 曾经有个 bug：管理员填的 Dify 会在同一浏览器里被下一个账号看到。
> v3.5 已修（换账号时会清掉浏览器里上一个人的 Dify 缓存），服务器端也不再"继承"。

## 二、服务器版升级

### 2.1 升级前（10 分钟，必做）

```bash
cd /home/lingxi

# ① 停服务
sudo systemctl stop lingxi

# ② 备份数据库（务必）
venv/bin/python app/dbbackup.py save "升级前 v3.0"

# ③ 备份配置（升级包不含它，但保险）
cp config.ini config.ini.bak-升级前

# ④ 拍个源码快照（可选，出事了能对比）
bash run/deploy/snapshot_server.sh
```

### 2.2 升级

```bash
# ① 解压升级包到临时目录
cd /tmp && unzip 灵犀-v3.5-升级包.zip -d /tmp/lingxi-v35

# ② 覆盖 app/（保留 data/、models/、venv/、config.ini）
cd /home/lingxi
rsync -av --delete /tmp/lingxi-v35/app/ ./app/

# ③ ★ 确认服务器身份没被破坏
ls run/deploy/sync_db.py
# 期望：No such file or directory   ← 这是对的（服务器不该有）
# 如果存在了：rm run/deploy/sync_db.py

# ④ 启动
sudo systemctl start lingxi

# ⑤ 等模型加载（至少 25 秒，别急着测）
sleep 30
curl -s localhost:8199/health | head -c 120
```

> **用部署脚本也行**（推荐，会逐个文件校验 sha256 再重启）：
> ```powershell
> venv\Scripts\python.exe run\deploy\deploy_app.py
> ```

### 2.3 升级后验证（6 项）

```bash
# ① 健康检查
curl -s localhost:8199/health | grep -o '"status":"ok"'

# ② 未登录必须被挡
curl -s -o /dev/null -w '%{http_code}\n' localhost:8199/api/folders
# 期望：401

# ③ 首页不能是嵌入调试页
curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' localhost:8199/
# 期望：302 → /static/search.html

# ④ 接口文档应关闭
curl -s -o /dev/null -w '%{http_code}\n' localhost:8199/docs
# 期望：404

# ⑤ 新版共享模块在位
ls app/difyshare.py && grep -c 'api/dify/shared' app/filesearch.py
# 期望：文件存在 + 至少 1

# ⑥ 哈希文件恢复长缓存
curl -sI localhost:8199/static/app.*.js | grep -i cache-control
# 期望：public, max-age=31536000, immutable
```

### 2.4 外网入口

隧道配置不用改（还是指向 `http://127.0.0.1:8199`）。确认 cloudflared 还在：

```bash
ps aux | grep -c '[c]loudflared'    # 期望：1
```

## 三、回滚方案（升级出问题时）

### 3.1 最快回滚（5 分钟）

```bash
# 服务器
sudo systemctl stop lingxi
cp -r /path/to/旧的app备份/app ./app
sudo systemctl start lingxi
```

**前提**：升级前备份了 `app/`（或拍过快照）。

### 3.2 数据库回滚（数据出问题时）

```bash
venv/bin/python app/dbbackup.py list
venv/bin/python app/dbbackup.py restore 20261022-010000
```

⚠ 恢复数据库会丢失备份之后的改动。**先停服务再恢复**。

### 3.3 完整回滚（回到 v3.0）

1. 用升级前的 `app/` 备份覆盖回去
2. 用升级前的数据库备份恢复 `data/index/index.db`
3. 恢复 `config.ini.bak-升级前`
4. 启动，浏览器 Ctrl+F5

> v3.5 没改数据库结构，所以**只回滚代码**通常就够，数据不用动。

## 四、升级后常见问题

### Q1：页面样式全乱了 / 图片不显示

前端文件名带哈希。确认目录里只有一个 `app.*.js` / `app.*.css`：

```bash
ls app/static/app.*.js
```

然后 **Ctrl + F5**。

### Q2：登录后马上又被踢回登录页

外网走 HTTPS 时 cookie 要带 `secure`，代码会按 `X-Forwarded-Proto` 自动判断。
如果还有问题，检查反向代理有没有传这个头。

### Q3：点「保存并验证」总说账号或密码不对

v3.5 之前这个提示**也可能**是那个字段名 bug 造成的（v3.5 已修）。
现在如果还报，就是真的不对：
- 填的是**服务器上**的账号吗？
- 该账号在服务器上是不是 `active`？
- 地址有没有多余路径（只填到端口）

### Q4：普通用户看不到文件夹

按归属隔离是设计如此。让管理员分配：
界面「文件夹 → 归属」，或 `run/assign_owner.py --to <用户id>`。

### Q5：Dify 勾了但检索不到

- 地址只填到端口（`/v1` 会被自动去掉）
- 知识库 ID 要 36 位完整 UUID（不完整会直接提示"少了几位"）
- 共享给别人的库，对方要能在自己卡片下方看到「🤝 别人共享给我的库」

### Q6：`/docs` 打不开

**服务器上是故意的**（关掉了）。本机版仍然开放。

### Q7：旧页面还显示中文乱码 / 布局是老的

纯粹是缓存：Ctrl + F5。v3.5 起旧哈希文件会返回"自动刷新一次"的脚本，
正常情况下你不用管。

## 六、版本对照

| 项 | v3.0 | v3.5 |
|---|---|---|
| 主标签 | 6 个（含人物·文件夹） | **5 个**（人物并入设置） |
| 设置页 | 15 张卡片一条长龙 | **4 个二级分类** |
| 首屏「运行中」 | 14.3 秒 | **3.0 秒** |
| 轮询 | 不分页面常驻 | **按当前页门控** |
| Dify | 只有聊天页，全局可见 | **聊天 + 知识库问答**，个人私有 + 可共享 |
| 服务器连接 | 保存并试连（只探测端口） | **保存并验证**（真登录、显示身份，账号密码必填） |
| 上传到服务器 | 可自行填账号 | **只认验证过的身份** |
| 静态缓存 | 全部 no-cache | 哈希文件 **immutable**，HTML 仍 no-cache |
