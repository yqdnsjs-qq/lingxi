## 2. 这一版做了什么（按主题）

### 2.1 多人版（核心）

**判据是"这台机器是不是他自己的"，不是角色。** 代码里看 `run/deploy/sync_db.py` 在不在：

```python
_can_index_here() = (ROOT/"run"/"deploy"/"sync_db.py").is_file()
# True  = 建库机（本机版）
# False = 服务器版
```

| 场景 | `_view_mode` | 能建库 | 能管服务器 |
|---|---|---|---|
| 本机 + 任何人 | `personal` | **能** | — |
| 服务器 + 管理员 | `admin` | 不能 | 能 |
| 服务器 + 普通用户 | `member` | 不能 | 不能 |

**⚠ 重要（2026-10-22 项目主澄清）**：
> "本机版用户或管理员应该**唯一区别是能不能管理操作服务器**而已，
>  但本机建库打标应该都可以用才行"

所以**本机功能全开**（谁登录都能建库/索引/打标），数据可见性才按归属隔离。
不要改回"本机普通用户不能建库"——那是我改错过一次的。

### 2.2 权限三档

| 函数 | 管什么 | 本机 | 服务器 |
|---|---|---|---|
| `_need_admin_or_local` | 个人数据（备份/还原/快照/个人 API） | 登录即可 | 必须管理员 |
| `_need_builder` | 建库（加删文件夹/索引/打标/全局设置） | **登录即可** | 必须管理员 |
| `_need_admin` | 管服务器（users/shares/审批） | — | 必须管理员 |

### 2.3 数据隔离

三种共享状态：

| 状态 | 谁能看 | 谁能改 |
|---|---|---|
| 私有（无 ACL） | 本人 | 本人 |
| `visibility='shared'` | 所有登录用户 | 只有本人 |
| `folder_acl` | 名单里的人 | 只有本人 |

`[multi] local_strict`：
- `yes`（**默认**）→ 本机也按归属隔离
- `no` → 本机所有人看全部（个人专用）

**⚠ 易错点**：`multiuser.visible_folder_ids()` 的规则是
`vis == "shared" and (uid or owner == 0)`。
早期写成 `owner == 0 and vis == "shared"` 导致"归给管理员之后所有共享都失效" ✗

### 2.4 聊天（`app/chat_api.py`）

功能清单：

- 会话保存（`chat_conversation` / `chat_message` 表）
- SSE 流式（`POST /api/chat2/conversations/{id}/stream`）
- 联网搜索（Bing HTML 抓取，`app/websearch.py`）
- 本项目知识库检索（和搜索同一套引擎，按可见范围过滤）
- **Dify 多库合并**（每用户自己的多个 dataset，`app/difyclient.py`）
  - **2026-10-22 加**：「知识库问答」页（`POST /api/chat`）也能勾 **☁ Dify 一起查**，
    和本库片段一起进提示词；本库标 `[1] [2]`，Dify 标 `[D1] [D2]`，两套编号独立 ✓
  - 实现要点：`_who(request)` 取当前用户 → `store.prefs_all(uid, inherit_sensitive=…)`
    读 `eg2-difylist`（`eg2-dify*` 是敏感前缀，普通用户**不继承**管理员的库）
  - 只有 Dify 命中、本库没命中时也会作答（不再返回"没检索到"）；两路都没命中才提示
- 附件（图片走多模态 `image_url`，PDF/Office 走 `extract.extract()`）
- API 模型选择（`api:<index>` 走 `prefs["eg2-rmapilist"]`）
- 导出（md / json）

**API 共享规则**（2026-10-22 项目主定的）：

| 配置 | 谁能用 |
|---|---|
| `api_key` 为空 | **所有登录用户**（公共推理资源，如服务器上的 llama.cpp） |
| 有 key + `share: true` | 所有人 |
| 有 key + `share_to: [4]` | 名单里的人 |
| 有 key + 都没设 | 只有本人/管理员 |
| **自己配的（`user_prefs` 里有）** | 永远可见（哪怕带 key） |

key **只在服务端用**，前端只拿模型名 ✓

### 2.5 账号

- 注册开关：`meta` 表 `auth.allow_register`，界面切换**立即生效**（不用改文件）
- 管理员能直接新建用户（`POST /api/auth/users`），默认 `active`
- 用户能自己改名 / 改密码（`/api/auth/me/name`、`/api/auth/me/password`）
  - 改名要验密码、查重
  - 改密码要旧密码，改完踢掉**其它**会话（当前保留）
- 外网不暴露"有几个账号"（`/api/auth/status` 的 `users` 只在本机返回）

**⚠ 密码是 PBKDF2 + 每用户随机 salt**，验证必须用 `_check_pwd(pwd, stored)`。
我写过 `stored == _hash_pwd(pwd)`，永远不相等 ✗（踩过）

### 2.6 外网部署

**方案：Cloudflare Tunnel**（在服务器上跑，指向 `127.0.0.1:8199`）

为什么不用端口映射：运营商封 80/443，域名要带端口不美观。

**已开的守卫**：
```
EG2_ENFORCE_LOGIN=1    未登录访问业务接口 → 401
EG2_TRUST_PROXY=1      信任 X-Forwarded-Proto / CF-Connecting-IP
```

**服务器专属行为**（`_can_index_here()` 为假时）：
- `/` → 302 到搜索页（**不暴露嵌入调试页**）
- `/docs`、`/redoc`、`/openapi.json` → 404（关掉接口文档）
- 账号数量不外露

**已知问题：慢**。Cloudflare 把国内流量导到法兰克福/阿姆斯特丹
（`cf-ray: ...-FRA`），首屏 8~9 秒。已做的缓解：
- gzip（305 KB → 111 KB 传输）
- 拆包（HTML 38 KB + JS/CSS 独立，文件名带内容哈希）

**再快只能**：国内 VPS + frp（用户暂不做），或备案域名 + CF 中国网络（要企业版）。

### 2.7 静态资源与缓存

- `search.html` 拆成 `search.html` + `app.<hash>.js` + `app.<hash>.css`
- 带哈希的 → `Cache-Control: public, max-age=31536000, immutable`
- HTML → `no-store` + `CDN-Cache-Control: no-store`（**否则 Cloudflare 的
  Browser Cache TTL 会把它改成 4 小时** ✗ 踩过）

**改前端 JS/CSS 后必须跑** `run/rehash_static.py`，它会重算哈希、改名、
更新 HTML 引用、删旧文件。不跑的话浏览器会拿到旧代码 ✗

### 2.8 OCR（可选组件）

三个引擎，各在**独立环境**里（子进程调用，避免依赖冲突）：

| 引擎 | 体积 | 显存 |
|---|---|---|
| RapidOCR | 0.26 GB | 不占（CPU） |
| PP-OCRv6 | 3.81 GB | 要 GPU |
| MinerU | 11.63 GB | 要 GPU |

**路径三级优先**（2026-10-22 项目主："做进界面吧"）：
```
① config.ini 的 [ocr] 段（设置页填的）← 最优先
② 环境变量 EG2_OCR_*（兼容 ocr-env.bat）
③ 代码默认值 D:\GJ\...（开发机）
```

界面位置：设置 → OCR → 「引擎路径」（折叠区，默认收起）。

### 2.9 发布包

`run/build_release.py` 生成三个包（**白名单打包**，不是整目录压缩）：

| 包 | 内容 | 关键差异 |
|---|---|---|
| `灵犀-v3.0-本机版.zip` | 代码 + bat + 文档 | **含** `run/deploy/sync_db.py` |
| `灵犀-v3.0-服务器版.zip` | 代码 + install.sh + service | **不含** `sync_db.py` |
| `灵犀-v3.0-升级包.zip` | 只有 `app/` + 文档 | 不含 config.ini / bat |

**本机版是通用版**：不再分管理员包/用户包，谁登录看谁的角色（但本机功能全开）。

**打包必须排除**：`run/deploy/keys/`（SSH 私钥）、`_local_db_backup*.db`（278 MB）、
所有 `.log`、`__pycache__`。`config.ini` 要**脱敏**（清 token / key）。

## 4. 工作流铁律（照做能少走弯路）

```powershell
# 1. 改代码
# 2. 重启本机（必须！deploy_app.py 不会重启本机）
& .\venv\Scripts\python.exe -u run\restart_server.py --no-ui
Start-Sleep -Seconds 30        # 模型加载要时间

# 3. 真实请求验证（不是"编译通过"就完事）
# 4. 拍快照
& .\venv\Scripts\python.exe -u run\snapshot.py "说明"
& .\venv\Scripts\python.exe -u app\dbbackup.py save "说明"

# 5. 同步到服务器（只传 app/，不重启本机）
& .\venv\Scripts\python.exe -u run\deploy\deploy_app.py
```

**动数据库结构前**必须先 `dbbackup.py save`（增量，秒级）。

**服务器上跑脚本用 `venv/bin/python`**（系统 python 没 numpy）。
服务器重启后**等 25 秒**再测（不然全是 HTTP 0）。

## 6. 踩过的坑（血泪清单）

### 6.1 数据库 / 权限

1. **`store.stats()` 没有用户作用域** → 普通用户看到全站统计。加了 `folder_ids` 参数，
   `[]` 必须返回全零（不能退化回全站）。
2. **`visible_folder_ids` 规则写反** → `owner == 0 and vis == "shared"` 导致所有共享失效。
   正确：`vis == "shared" and (uid or owner == 0)`。
3. **5 处直接调用 `multiuser.writable_folder_ids`** 绕过了 `_writable()` → 本机普通用户
   只看到 3 个文件夹。统一包一层 `None if _local_open(...) else ...`。
4. **`_need_builder` 第一次改反了**（把本机普通用户的建库禁了）。项目主明确：
   **本机功能全开**，唯一区别是能不能管服务器。
5. **密码验证用错函数** → PBKDF2 + salt，必须 `_check_pwd()`，不能直接比哈希。

### 6.2 聊天

6. **`pick = api:<i>` 漏了 `eg2-rmhdr`** → opencode 需要 `x-opencode-session` 头，
   漏了就是 502。
7. **`chat2` 没注册 `dbreload`** → 服务重启后 `store` 连接已关闭，所有聊天接口
   **静默返回空**（被 `except` 吞了）。日志里是
   `Cannot operate on a closed database`。
   **任何 `create_router(cfg, store, ...)` 都必须注册 `dbreload`。**
8. **`newChat2Conv` 漏 `Content-Type`** → FastAPI 按 text/plain 收 → 422 →
   前端显示 `[object Object]`（因为 422 的 `detail` 是数组，`new Error(数组)` = `[object Object]`）。
9. **模型吐 ` thinking` 思考过程** → 后端存库前 + 前端渲染时都要 `strip_think`。
10. **`deepseek-v4.1-flash` 是"假流式"**（首字节 = 总耗时 10 秒，整段蹦出来）。
    切到 `qwen3.8-flash` 后 4 秒。

### 6.3 前端

11. **`resp.headers["X"] = v` 对 Starlette 的 `FileResponse` 不生效** →
    必须在 **ASGI 消息层**改（包一层 `send`，改 `http.response.start` 的 headers）。
12. **`StaticFiles.get_response(path, scope)` 里拿不到 `query_string`** →
    不能用 `?v=hash` 判断缓存，改用**文件名带哈希**。
13. **拆 `search.html` 时索引错位** → 先删 `<style>` 再删 `<script>`，但 script 的
    start/end 是按原文件算的，删完 style 就全错位了 ✗
    正确：所有区间**混在一起按 start 倒序**一次删完。
14. **`login.html` 压根没有 logo** → 外网打开看到的是登录页（空），内网看到的是
    `search.html`（有 logo）。是"页面不同"不是"图片没加载"。
15. **浏览器缓存了"没图标"状态** → favicon 要带版本号 `?v=20261022a`。
16. **Cloudflare 把 `no-cache` 改成 `max-age=14400`**（Browser Cache TTL）→
    改页面后用户那边还是旧的。用 `no-store` + `CDN-Cache-Control: no-store`。

### 6.4 部署

17. **`deploy_app.py` 不同步 `static/*.png`**（白名单只有 `.html/.js/.css/.svg/.ico`）
    → 加图标后服务器上没有。
18. **PowerShell 会吃掉内联 Python 里的 `$(`、反引号、`\r\n`** → 多次把脚本搞坏。
    **正确做法：用 `write` 工具写成 `.py` 文件再执行，不要内联。**
19. **PowerShell `-Command` 是整体解析的** → 后面有语法错误，**前面整段都不执行**
    （我有过一次 `deploy_app.py` 因此没跑，误判"改了没生效"）。
20. **`app.openapi_url = None` 会让 `/docs` 变 500**（路由早注册了，生成文档时崩）。
    加 404 覆盖路由也没用（被自动生成的抢了）。
    **正确：从 `app.router.routes` 里删掉那 4 条。**
21. **Cloudflare Tunnel 在国内不可行** —— 实测 `api.cloudflare.com` /
    `argotunnel.com` / `github.com` 全部超时。但项目主已在自己网络侧搞定隧道，
    服务器→CF 的**出站**不通也不影响（隧道是 cloudflared 主动连出去的）。

### 6.5 测试卫生

22. **永远不要用 `DELETE FROM <table>` 做测试清理** —— 我有一次
    `DELETE FROM user_prefs` 把项目主的真实 API 配置删了 ✗
    **只删自己写的那几个 key。**
23. **测试账号残留导致误判** —— 上次跑完没清，这次 `create_user` 撞名失败被吞，
    密码还是上次改过的 → 用例全红。测试前先清测试数据。

## 9. 项目主的工作习惯（很重要）

- **全程中文**，不要夹英文单词（代码标识符除外）
- 每完成一小步：**拍快照 → 真发请求验证 → 中文报告**（做了什么 / 证据 / 还剩什么）
- 报告要**给证据**（实测数字、状态码），不要只说"改好了"
- **不要编造**：不确定就说"没验证"；他追问过时间，我瞎说"凌晨三点"被纠正过
- 他喜欢**直接做**，不喜欢被反复问；但**方案有分歧时要先说清取舍**
- 他会在界面上实际点，所以**前端改动必须能被看到**（build 号要变）
